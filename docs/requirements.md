# 봐드림 기능 요구사항

제품이 **지금 실제로 어떻게 동작하는지** 적은 기준 문서다. 기능을 바꿀 때는 이 문서의 요구사항 ID(예: `CALL-03`)로 이야기하고, 코드를 바꾸는 커밋에서 이 문서도 같이 고친다.

- 기준일: 2026-09-27
- 상태 표기: ✅ 구현됨 · 🚧 일부만 구현됨 (제약 참고) · ⬜ 예정
- 각 요구사항은 **동작**(무엇을 하나), **확인**(폰으로 어떻게 확인하나), **제약**(안 되는 것·주의할 점)으로 적는다
- 알려진 버그는 맨 아래 [알려진 문제](#알려진-문제)에 `BUG-번호`로 모아 두고, 관련 요구사항에서 가리킨다

## 용어

| 용어 | 뜻 |
|---|---|
| 엔지니어 | 로그인해서 원격 A/S를 하는 사람 (폰 또는 PC 웹) |
| 고객 | 문자로 받은 링크를 열어 폰 카메라로 비춰 주는 사람. 로그인 없음 |
| 세션 | 원격 A/S 한 건. 화면에서는 **상담**이라고 부른다(사장님·엔지니어에게 익숙한 말). 코드와 DB에서는 `room`(방) |
| 링크 토큰 | 세션마다 붙는 32자리 추측 불가능한 값. 고객 링크 끝에 붙는다 (`/join/토큰`) → [ROOM-12](#room-12--고객-링크-토큰-) |
| 세션 상태 | **대기 중**(아직 연결된 적 없음) → **연결됨**(한 번이라도 연결된 적 있음) → **종료**(엔지니어가 종료 처리함). 연결에 실패한 채 종료하면 '대기 중'에서 바로 '종료'가 된다 |
| TURN | 폰끼리 직접 연결이 안 될 때(5G끼리 등) 영상을 중간에서 전달해 주는 서버. Cloudflare를 쓴다 |

## 1. 엔지니어 로그인·접근 (AUTH)

### AUTH-01 · 첫 화면 ✅
- **동작**: 사이트 주소를 열면 봐드림 로고, 큰 제목 '고장 난 곳, 기사님이 봐드려요'와 '문자 속 링크를 누르고 폰 카메라로 비추면 돼요'가 보인다. 그 아래 옅은 파란 카드에 링크 대신 주소를 친 **사장님용 안내**('A/S 받으시는 사장님께 / 기사님이 보낸 문자 속 링크를 눌러 주세요. 이 화면에서는 하실 게 없어요.'), 아이콘과 함께 특징 세 줄(앱은 안 깔아도 돼요 / 링크 열고 카메라만 켜면 끝이에요, 누를 곳을 짚어 드려요 / 화면에 빨간 동그라미가 떠요, 통화 영상은 남기지 않아요 / 사진을 찍으면 그때마다 알림이 떠요), 화면 아래에 붙은 회색 '엔지니어 로그인' 버튼이 있다. 이미 로그인했으면 버튼을 눌렀을 때 바로 대시보드로 간다.
- **왜**: 이 화면에 오는 사람은 주소를 직접 친 고객과 엔지니어 둘이다. 고객이 로그인 버튼을 누르지 않게, 파란(지금 누를 것) 버튼은 두지 않고 고객 안내를 먼저 보여 준다.
- **확인**: 배포 주소 첫 화면을 연다. 로그아웃 상태면 버튼이 로그인 화면으로, 로그인 상태면 대시보드로 간다.
- **관련 코드**: `src/app/page.tsx`

### AUTH-02 · 이메일·비밀번호 로그인 ✅
- **동작**: 로고, 큰 제목 '엔지니어 계정으로 로그인해 주세요', 이메일·비밀번호 입력칸(회색 면, 높이 56px, 18px 글씨, 누르면 흰 바탕에 파란 테두리)이 있고, 화면 아래에 붙은 파란 '로그인'(64px)과 그 아래 '계정은 관리자에게 받아 주세요. A/S 받으시는 사장님은 로그인할 필요가 없어요.'가 있다. 이메일 칸에는 이메일 키보드가 뜨고, 저장된 비밀번호 자동 채우기가 된다. 비밀번호 칸 오른쪽 눈 모양 버튼으로 비밀번호를 보이게·숨기게 할 수 있다. 처리 중에는 버튼이 '로그인 중…'(도는 표시)으로 바뀌고 눌리지 않는다. 성공하면 대시보드로 간다.
- **확인**: `/login`에서 로그인해 대시보드가 나오는지 본다. 눈 모양을 눌러 비밀번호가 보이는지 본다.
- **제약**: 회원가입·비밀번호 찾기·비밀번호 변경 화면이 없다. 계정은 [OPS-03](#ops-03--엔지니어-계정-만들기-)대로 Supabase에서 직접 만든다.
- **관련 코드**: `src/app/(engineer)/login/`

### AUTH-03 · 로그인 실패 안내 ✅
- **동작**: 이메일이나 비밀번호가 틀리면 로그인 화면에 머물고, 빨간 상자에 '이메일이나 비밀번호가 맞지 않아요.'가 나오며 입력칸 테두리가 빨개진다. 어느 쪽이 틀렸는지는 알려 주지 않는다. 입력한 이메일은 그대로 남고 비밀번호 칸만 비워진다([BUG-20](#bug-20--로그인에-실패하면-이메일까지-지워짐-낮음) 해결).
- **확인**: 틀린 비밀번호로 로그인해 본다. 이메일이 남아 있는지 본다.
- **제약**: 서버 장애나 시도 횟수 제한도 같은 문구로 나온다.

### AUTH-04 · 엔지니어 화면 보호 ✅
- **동작**: 로그인하지 않고 대시보드, 세션 화면, 통계 화면을 열면 로그인 화면으로 보낸다. 로그인하면 원래 열려던 화면으로 돌아간다. 이미 로그인한 상태로 로그인 화면을 열면 대시보드로 보낸다.
- **확인**: 시크릿 창에서 `/dashboard`를 연다. 로그인 화면으로 바뀌고, 로그인하면 대시보드로 간다.
- **제약**: 돌아갈 주소는 같은 사이트 안의 경로만 허용하고, 아니면 대시보드로 간다([BUG-08](#bug-08--로그인-후-이동-주소-검사에-빈틈-중간보안) 해결).

### AUTH-05 · 로그인 유지 ✅
- **동작**: 브라우저를 닫았다 열어도 로그인이 유지되고, 만료가 가까워지면 자동으로 갱신된다. 로그인 정보는 쿠키에만 둔다.
- **확인**: 로그인 후 브라우저를 완전히 닫았다 다시 열고 `/dashboard`가 바로 열리는지 본다.

### AUTH-06 · 로그아웃 ✅
- **동작**: 대시보드 오른쪽 위 '로그아웃'(아이콘과 글자)을 누르면 로그인 화면으로 간다.
- **제약**: 같은 계정으로 로그인한 **모든 기기**가 함께 로그아웃된다 (PC에서 로그아웃하면 폰도 풀림). 세션 화면에는 로그아웃 버튼이 없다.

### AUTH-07 · 고객 쪽은 로그인 없이 공개 ✅
- **동작**: 고객 링크(`/join/토큰`)와 고객이 쓰는 서버 기능(TURN 발급, 지표 기록)은 로그인 없이 쓸 수 있다. 로그인 보호는 대시보드와 세션 화면에만 있다.
- **확인**: 로그인한 적 없는 폰에서 고객 링크를 열면 바로 '카메라 켜고 시작하기' 화면이 나온다.

### AUTH-08 · 자기 세션만 보기 ✅
- **동작**: 엔지니어는 자기가 만든 세션만 목록에서 보고, 열고, 종료할 수 있다. 다른 엔지니어의 세션 주소를 열면 404 화면이 나온다.
- **확인**: 엔지니어 계정 두 개로 서로의 세션이 안 보이는지 확인한다.
- **제약**: 이 보호는 Supabase 보안 정책(RLS)에 달려 있어서 `schema.sql`을 실행해 둬야 한다. 남의 세션이나 없는 주소를 열면 '페이지를 찾을 수 없어요 / 주소가 틀렸거나 볼 수 없는 상담이에요. A/S 받으시는 사장님은 문자 속 링크를 다시 눌러 주세요.'와 '처음으로' 버튼이 나온다.

## 2. 세션 만들기·공유·종료 (ROOM)

### ROOM-01 · 새 세션 만들기 ✅
- **동작**: 대시보드의 파란 '＋ 새 A/S 시작'(64px)을 한 번 누르면 세션이 만들어지고 바로 세션 화면으로 간다. 누르는 순간 마이크도 미리 요청해 두므로, 세션 화면은 버튼 없이 곧바로 '고객님께 링크를 보내 주세요' 화면이 된다([CALL-01](#call-01--엔지니어-연결-준비-), [ROOM-05](#room-05--세션-화면-)). 종료·만료된 상담 화면([ROOM-11](#room-11--종료된-세션-화면-))에도 같은 버튼이 있다.
- **확인**: 버튼을 눌러 마이크 허용 뒤 '고객님께 링크를 보내 주세요' 화면으로 넘어가는지 본다.
- **제약**: 처리 중에는 버튼이 '만드는 중…'(도는 표시)으로 바뀌고 잠겨서 여러 번 눌러도 하나만 생긴다. 실패하면 '잠깐 문제가 생겼어요 / 조금 있다가 다시 눌러 주세요.'와 '다시 시도' 버튼이 나온다.

### ROOM-02 · 접속 코드 — 폐기 (2026-09-24)
예전에는 세션마다 6자리 코드를 만들어 링크와 화면에 썼다. 링크는 [ROOM-12](#room-12--고객-링크-토큰-)의 토큰으로 바뀌었고, 고객이 코드를 보거나 입력할 일이 없어 화면에서도 뺐다. 세션은 만든 시각으로 구분한다. 예전 세션의 코드는 DB에만 남아 있다.

### ROOM-03 · 초대 링크 유효기간 🚧
- **동작**: 링크는 세션을 만들고 24시간이 지나거나, 엔지니어가 종료 처리하면 더 이상 쓸 수 없다. 고객이 열면 '상담이 이미 끝났어요'(24시간이 지났으면 '링크가 만료됐어요') 안내가 나온다([JOIN-03](#join-03--잘못된-링크-안내-)).
- **확인**: 세션을 종료한 뒤 같은 링크를 열어 본다.
- **제약**:
  - **1회용이 아니다.** 유효기간 안에는 같은 링크를 몇 번이든, 여러 기기에서 열 수 있다. 여러 기기에서 열면 가장 늦게 연 기기가 이어받는다 → [CALL-13](#call-13--다른-기기에서-이어받기-)
  - 24시간이 지나면 대시보드에는 '만료'로, 세션 화면에는 만료 안내로 보인다([ROOM-04](#room-04--최근-세션-목록-), [ROOM-11](#room-11--종료된-세션-화면-)). 다만 DB 상태가 저절로 '종료'가 되지는 않아서 원격 해결 여부는 비어 있다(원격 해결률 계산에서 빠짐).

### ROOM-04 · 최근 세션 목록 ✅
- **동작**: 대시보드(상담 목록)는 회색 바탕에 흰 카드로 나뉜다. 위에서부터 로고·'통계'·'로그아웃', 큰 제목 '김도현님, 안녕하세요'(엔지니어 표시 이름이 없으면 '안녕하세요', [OPS-03](#ops-03--엔지니어-계정-만들기-)), **이번 달 카드**, **진행 중** 카드, **최근 상담** 카드 순서이고, 파란 '＋ 새 A/S 시작'([ROOM-01](#room-01--새-세션-만들기-))은 한 손으로 누르게 화면 아래에 붙어 있다(스크롤해도 그 자리). 내 세션을 최신순으로 최대 20개 가져와 두 카드에 나눠 보여 준다. 줄을 누르면 그 세션 화면으로 간다.
  - 이번 달 카드(누르면 통계 화면 [DATA-06](#data-06--통계-화면-)): '이번 달 원격 해결률 >', 가장 큰 숫자로 해결률과 옆에 초록 '출장 N건 줄였어요', 그 비율만큼 찬 초록 막대, 아래 한 줄에 '상담 N건'·'평균 시간 12분'. 기록이 없으면 '—'·'아직 기록이 없어요'(막대 없음).
  - 진행 중 N(종료·만료 전): 줄마다 **이어서 할 일이 먼저** 보인다 — 주황 시계 아이콘 '고객님 기다리는 중'(아래 '오늘 오후 5:03 · 링크 N시간 남음') 또는 파란 연필 아이콘 '결과 기록 전'(아래 만든 시각), 오른쪽 '>'. 줄을 누를 때도 마이크를 미리 요청해 세션 화면이 바로 통화 대기로 들어간다([CALL-01](#call-01--엔지니어-연결-준비-)). 없으면 카드가 안 보인다.
  - 최근 상담(끝났거나 만료): 만든 시각, 걸린 시간('12분 걸림') 또는 '기록 없음', 오른쪽 상태 칩 — 초록 '원격 해결', 빨강 '방문 필요', 회색 '연결 안 됨'(연결 없이 닫음), 회색 '만료'(답 없이 24시간 지남).
  - 시각은 '오늘 오후 5:03', '어제 오전 9:10', '9월 25일 (목) 오후 2:00'처럼 한국 시간으로 쓴다([BUG-16](#bug-16--시각이-pm-0500처럼-영어로-섞여-나옴-낮음) 해결).
  - 세션이 하나도 없으면 최근 상담 카드에 '아직 상담이 없어요 / 아래 '새 A/S 시작'을 눌러 보세요'.
- **왜**: 원격 해결률은 영업 자료가 되는 핵심 지표라 첫 화면 맨 위에, '줄인 출장 수'처럼 사장님·엔지니어가 체감하는 말로 보여 준다.
- **확인**: 세션 몇 개를 만들고 끝낸 뒤 구역과 칩, 이번 달 카드 숫자를 본다.
- **제약**: 20개를 넘으면 오래된 것은 안 보인다. 화면을 새로고침해야 상태가 바뀐다. 고객 이름·가게 이름을 저장하지 않으므로([NFR-07](#nfr-07--고객-연락처는-저장하지-않음-)) 시각으로만 구분한다. 이번 달 카드는 한국 시간 1일 0시 이후 만든 세션을 센다. 해결률과 평균 시간은 [DATA-02](#data-02--핵심-지표-계산법-)처럼 **해결 여부를 답한 상담만**, 평균·걸린 시간은 **세션을 만든 때부터** 잰다.
- **관련 코드**: `src/app/(engineer)/dashboard/page.tsx`, `mic-ahead-link.tsx`, `src/components/ui/status-chip.tsx`·`bottom-cta.tsx`, `src/lib/format.ts`

### ROOM-05 · 세션 화면 ✅
- **동작**: 세션 화면은 **상태마다 할 일 하나만** 보여 준다. 화면 제목은 위쪽 바가 아니라 본문 맨 위에 크게(26px) 쓰고, 누를 것은 화면 아래에 붙는다. 위쪽 바는 '<'(상담 목록)와 오른쪽 작은 '상담 닫기'(연결된 적 있으면 '통화 종료', [ROOM-10](#room-10--종료와-출장-없이-해결-입력-))뿐이다.
  1. **마이크 켜기**(대시보드를 거치지 않고 열었거나 새로고침한 경우만): '마이크부터 켜 주세요 / 켜면 고객님께 보낼 링크가 나와요'와 파란 '마이크 켜고 연결 준비' → [CALL-01](#call-01--엔지니어-연결-준비-)
  2. **링크 보내기**: 제목 '고객님께 링크를 보내 주세요', 그 아래 '고객님이 카메라를 켜면 바로 연결돼요'. 회색 카드 **'보낼 문자'**에 보낼 문자([ROOM-06](#room-06--문자로-보내기-))를 말풍선으로 그대로 보여 준다(링크 주소 포함). 문자 버튼이 없는 PC에서는 같은 글을 '공유할 글'로 보여 주고, 공유하기도 없으면 '보낼 링크'로 링크 주소만 보여 준다(그 글을 보내는 버튼이 없어서). 그 아래 한 줄로 마이크 상태('마이크 켜짐' 초록 / '마이크 꺼짐' 노랑)와 '링크는 24시간 동안 쓸 수 있어요'. 아래쪽에 파란 '문자로 링크 보내기'([ROOM-06](#room-06--문자로-보내기-)), 그 아래 한 줄에 노란 '카톡 보내기'([ROOM-14](#room-14--카톡으로-바로-보내기-))·회색 '공유하기'([ROOM-07](#room-07--다른-앱으로-공유-))·회색 '링크 복사'([ROOM-08](#room-08--링크-복사-))가 아이콘 위·글자 아래로 나란히 선다. **이 기기에서 할 수 있는 것만 띄운다**: 문자는 폰에서만, 카톡 보내기는 카카오 키가 있을 때만, 공유하기는 기기 공유 창이 있는 브라우저에서만, 링크 복사는 늘. 그래서 PC에는 파란 문자 버튼이 없고 한 줄만 있다. 한 줄에 둘이면 두 칸, 셋이면 세 칸이다. 문자도 없고 링크 복사만 남으면 링크 복사가 파란 큰 버튼이 되고, 문자 아래 링크 복사 하나만 남으면 글자 버튼이 된다.
  3. **고객 기다리는 중**(링크를 보냈거나 고객이 링크를 열면 바뀜): 상태 동그라미(기다리는 중은 주황, 퍼지는 고리 · 곧 연결은 초록 · 막힘·실패는 빨강)와 **지금 기다리는 단계가 곧 제목**이다 — '고객님이 링크를 열기를 기다리고 있어요'(아래 '오늘 오후 5:03에 만든 상담이에요'; 연결된 적 있으면 '고객님을 다시 기다리고 있어요') → '고객님이 카메라를 켜기를 기다리고 있어요'(아래 '고객님이 카메라를 켜면 바로 연결돼요') → '곧 연결돼요'(아래 '고객님이 카메라를 켰어요. 잠시만 기다려 주세요.'). 카메라가 막히면 '고객님 카메라가 막혀 있어요'와 아래 빨간 글씨로 전화로 해 줄 말([ROOM-13](#room-13--고객-진행-상황-)). 그 아래 회색 카드 **고객 진행 상황**([ROOM-13](#room-13--고객-진행-상황-), 오른쪽 위에 마이크 상태), 접힌 **'고객님께 이렇게 말씀해 주세요'**(전화로 읽어 줄 말: '문자로 링크 보내 드렸어요. 누르시면 파란 버튼 카메라 켜고 시작하기가 있는데, 그거 누르시고 허용 누르시면 돼요. 그다음에 고장 난 데를 비춰 주세요.' — 고객 화면 버튼 이름과 같다. 첫마디는 어떻게 보냈는지 알 때만 채널을 말한다. '카톡 보내기'로 보냈으면 '카톡으로 보내 드렸어요. 거기 카메라 켜기 누르시면…'(카톡 카드의 버튼 이름), 공유하기·링크 복사였거나 고객이 먼저 열었으면 '링크 보내 드렸어요. 누르시면…'). 이제 누를 것이 없으므로 파란 버튼 대신 회색 '문자 다시 보내기'(폰에서만)와 그 아래 한 줄에 글자 버튼 '카톡 보내기'·'공유하기'·'링크 복사'(할 수 있는 것만). 문자도 없고 링크 복사만 남은 브라우저에서는 회색 큰 '링크 복사' 하나다.
  4. **통화**: 어두운 전체 화면 → [CALL-04](#call-04--엔지니어-통화-화면-)
  5. **결과 기록** → [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)
- **왜**: 고객이 링크를 열 때 엔지니어가 항상 기다리고 있게, 링크는 통화 대기가 켜진 뒤에만 보인다([BUG-17](#bug-17--연결-준비를-잊으면-고객이-계속-기다림-중간) 해결). 링크를 보낸 뒤 "고객이 뭘 하고 있는지 모르는" 시간이 가장 불안하므로 진행 상황을 보여 준다.
- **확인**: 대시보드 '새 A/S 시작' → 마이크 허용 → '고객님께 링크를 보내 주세요' 화면 → 보내기(또는 고객이 링크 열기) → '고객 기다리는 중'과 진행 상황 → 고객이 카메라를 켜면 통화 화면. 폰과 PC에서 뜨는 버튼이 다른지(폰은 문자 + 한 줄, PC는 한 줄만) 본다. 자동 테스트 `e2e/call-end.spec.ts`, 화면 카탈로그(`npm run screens`)의 '고객님께 링크를 보내 주세요 (E03)'·'카톡 보내기 → 고객 기다리는 중 (PC)'.
- **제약**: 링크 주소는 엔지니어가 지금 접속한 주소를 기준으로 만든다. 미리보기 주소로 들어왔으면 그 주소가 고객에게 간다. '문자로 링크 보내기'를 누르면 실제로 보냈는지와 상관없이 '보냈어요'로 본다(문자 앱에서 보냈는지 알 수 없음). 카톡 보내기는 친구 선택 창이 열리면(실제로 보냈는지와 상관없이), 공유하기는 공유 창에서 앱을 고르면 '보냈어요'로 본다. 통화 중에는 링크 화면이 숨고, 고객이 나가 대기로 돌아오면 다시 보인다. '상담 목록'으로 나가면 통화 대기도 끝나 고객이 연결되지 않는다(돌아와 '이어하기').
- **관련 코드**: `src/app/(engineer)/room/[id]/call-panel.tsx`, `waiting-view.tsx`, `share-buttons.tsx`

### ROOM-06 · 문자로 보내기 ✅
- **동작**: '문자로 링크 보내기'를 누르면 엔지니어 폰의 문자 앱을 열고 본문을 미리 채운다: '[봐드림] 원격 A/S 링크입니다. / 링크를 열고 '카메라 켜고 시작하기'를 누른 다음, 고장 난 곳을 비춰 주세요. 앱은 따로 안 깔아도 됩니다. / 링크'. 무엇인지·무엇을 누를지·설치가 없다는 것을 먼저 말해 모르는 링크(스미싱)로 보이지 않게 한다. 엔지니어 본인 번호로 가므로 문자 API나 발신번호 등록이 필요 없다. 아이폰과 안드로이드의 문자 앱 여는 방식 차이를 처리한다. 누르면 세션 화면이 '고객 기다리는 중'으로 바뀌고 버튼은 회색 '문자 다시 보내기'가 된다([ROOM-05](#room-05--세션-화면-)). 보내기 전 화면에 이 본문을 '보낼 문자' 말풍선으로 미리 보여 준다. 버튼은 **문자 앱이 있는 기기(아이폰·아이패드·안드로이드)에서만** 보인다. PC는 눌러도 문자 앱이 없어 아무 일이 없으므로 숨기고, PC에서는 카톡 보내기·공유하기·링크 복사로 보낸다.
- **확인**: 아이폰·안드로이드에서 버튼을 눌러 본문이 채워지는지 본다.
- **제약**: 받는 번호는 엔지니어가 직접 입력한다. 본문이 짧은 문자(90바이트)보다 길어 장문 문자(LMS)로 갈 수 있다. 폰인지는 브라우저가 알려 주는 기기 정보(User-Agent)로 가린다. 아이패드 사파리는 맥처럼 보여서 '맥인데 터치가 되면 아이패드'로 본다. 맥은 메시지 앱으로 문자를 보낼 수도 있지만 버튼을 숨긴다(맥 사파리의 '공유하기'에 메시지 앱이 있다). 반대로 문자 앱이 없는 와이파이 전용 안드로이드 태블릿에서도 버튼은 보인다.

### ROOM-07 · 다른 앱으로 공유 ✅
- **동작**: 기기 공유 창이 있는 브라우저(폰, 일부 PC 브라우저)에서만 '공유하기'(공유 모양 아이콘)가 보인다. 링크 보내기 화면에서는 한 줄의 회색 버튼, '고객 기다리는 중' 화면에서는 글자 버튼이다. 누르면 기기 공유 창이 문자와 같은 문구로 열리고, 카카오톡·밴드·라인·메시지 등 원하는 앱을 고른다. 공유 창을 그냥 닫아도 오류가 나지 않고 '보냈어요'로 보지 않는다. 카카오 키가 있어도 '카톡 보내기'([ROOM-14](#room-14--카톡으로-바로-보내기-))와 따로 선다. 카톡 친구가 아닌 사람이나 카톡 말고 다른 앱으로 보낼 때 쓴다.
- **확인**: 폰에서 '공유하기'를 눌러 공유 창이 뜨고, 고른 앱에 문구와 링크가 채워지는지 본다.
- **제약**: 카카오톡으로 받은 고객은 카톡 안에서 링크를 열게 되는데, 자동으로 인터넷 앱으로 다시 열어 준다 → [JOIN-10](#join-10--카카오톡-앱-안-브라우저-안내-)

### ROOM-08 · 링크 복사 ✅
- **동작**: 늘 보인다. 링크 주소만 복사하고 버튼이 2.5초 동안 '복사됐어요'(체크)로 바뀐다. 복사하면 세션 화면이 '고객 기다리는 중'으로 바뀐다. 다른 보내기 버튼(문자·카톡 보내기·공유하기)이 하나도 없는 브라우저에서는 링크 복사가 큰 버튼 하나가 된다(링크 보내기 화면은 파랑, 고객 기다리는 중 화면은 회색). 복사에 실패하면 '복사가 안 돼요 / 아래 주소를 직접 복사해 주세요'와 주소가 나온다(주소는 한 번 누르면 전체가 골라진다)([BUG-19](#bug-19--링크-복사에-실패해도-안내가-없음-낮음) 해결).

### ROOM-09 · 세션 상태 바뀌는 시점 ✅
- **동작**: 만들 때 '대기 중' → 엔지니어 화면에서 처음 영상이 연결되면 '연결됨' → 엔지니어가 [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)으로 종료하면 '종료'. 한 번도 연결되지 않은 세션을 '상담 닫기'로 닫으면 '대기 중'에서 바로 '종료'가 되고 원격 해결 여부는 비워 둔다.
- **제약**: '연결됨'은 "지금 통화 중"이 아니라 "한 번이라도 연결됐었다"는 뜻이다. 끊겨도 '대기 중'으로 돌아가지 않는다. 엔지니어가 세션 화면을 열어 둔 상태에서 연결돼야 바뀐다.

### ROOM-10 · 종료와 '출장 없이 해결?' 입력 ✅
- **동작**: 세션 화면 어느 단계에서든 끝낼 수 있다. 버튼은 세션이 **한 번이라도 연결됐는지**에 따라 다르다.
  - **연결된 적 있음**: 통화 화면의 빨간 '종료'(PC는 위쪽 '통화 종료', 대기 화면은 오른쪽 위 '통화 종료')를 누르면 아래에서 **'통화를 끝낼까요? / 고객님 화면도 같이 끊겨요. 끝나면 결과를 남겨 주세요.'** 창이 올라온다(대기 화면에서는 '상담을 끝낼까요?'). 창이 떠 있는 동안 **통화는 계속된다**. 빨간 '통화 끝내기'를 누르면 고객 화면이 '상담이 끝났어요'로 바뀌고 **결과 기록** 화면으로 간다. '계속 통화하기'(대기 화면은 '취소')나 창 바깥을 누르면 창만 닫힌다.
  - **결과 기록**: 이 화면의 할 일은 질문 하나라 **질문이 곧 제목**이다 — 큰 글씨 **'출장 없이 해결됐나요?'**와 '고른 답이 원격 해결률에 들어가요', 바로 아래 두 칸(64px) '네, 원격으로 해결했어요' / '아니요, 방문이 필요해요'. 칸은 회색 면이고, 하나를 고르면 흰 바탕에 진한 테두리와 체크가 되고(다시 골라 바꿀 수 있다), 그때 화면 아래 파란 **'기록하고 끝내기'**가 눌린다(고르기 전엔 잠김). 그 아래 참고로 회색 카드 '통화 요약'(만든 시각, 통화 시간, 방향 지시 N번, 가리키기·그리기 N번). 누르면 세션이 '종료'로 저장되고(종료 시각, 원격 해결 여부 포함) 대시보드로 간다. 건너뛰기는 없다.
  - **찍은 사진이 있으면**([CALL-16](#call-16--사진-찍기-)) 두 답과 통화 요약 사이에 회색 카드 '통화 중 찍은 사진 N장 / 저장 안 하면 이 화면을 나갈 때 지워져요.', 작은 사진들, 흰 '사진 N장 폰에 저장'(저장한 뒤에는 '폰에 저장했어요.'와 '다시 저장하기'). 저장하지 않은 채 '기록하고 끝내기'를 누르면 '찍은 사진 N장을 저장할까요? / 저장 안 하면 사진은 지워져요.' 창이 뜬다 — 파란 '사진 저장하고 끝내기'(저장이 끝나면 기록하고 끝낸다) / '저장 안 하고 끝내기'.
  - 두 답은 **같은 모양·같은 크기**다. 한쪽만 강조하면 원격 해결률(핵심 지표)이 그쪽으로 기울기 때문이다.
  - **연결된 적 없음**(고객이 안 들어왔거나 연결에 실패): '상담 닫기'를 누르면 '상담을 닫을까요? / 고객님께 보낸 링크도 더는 안 열려요.' 창이 뜬다. 빨간 '닫기'를 누르면 해결 여부를 묻지 않고 종료한다(원격 해결률 계산에서 빠짐). 기다리던 고객 화면은 '상담이 끝났어요'로 바뀐다. '취소'를 누르면 돌아간다. '연결 준비'를 처리하는 동안에는 이 버튼이 잠긴다.
  - **고객이 먼저 종료**: 엔지니어 화면이 결과 기록 화면으로 바뀌고 맨 위(제목 위)에 회색 띠 '고객님이 통화를 끝냈어요 / 고객님이 링크를 다시 열면 통화로 돌아가요.'가 뜬다. '기록하고 끝내기'를 누르기 전에 고객이 '다시 연결'하면 통화로 돌아간다.
  - 창이 뜬 직후(0.6초)의 탭은 무시한다('통화 끝내기', '계속 통화하기', 창 바깥 모두). 종료 버튼을 두 번 눌러 두 번째 탭이 창 버튼에 떨어지는 것을 막기 위해서다.
  - 기록하기 전에 다른 기기가 이어받으면([CALL-13](#call-13--다른-기기에서-이어받기-)) 이 기기는 '다른 기기에서 이어받았어요'로 바뀐다. 기록은 이어받은 기기에서 한다([BUG-18](#bug-18--답하기-전에-다른-기기가-이어받아도-질문이-남음-낮음) 해결).
  - 로그인이 풀린 상태에서 기록하면 로그인 화면으로 가고, 다시 로그인하면 이 세션 화면으로 돌아온다(기록은 다시 해야 한다). 인증 서버가 잠깐 응답하지 않은 경우는 로그인 화면 대신 '저장에 실패했어요'로 다시 누르게 한다.
  - 저장하는 동안 버튼은 '저장하는 중…'(도는 표시)으로 잠기고, 실패하면 '저장에 실패했어요. 다시 눌러 주세요.'가 나온다. 고객에게는 이미 종료를 알린 뒤라 되돌릴 수 없다. 고객이 먼저 끊은 경우에는 저장에 실패해도 계속 기다리므로, 고객이 링크를 다시 열면 이어진다.
- **왜**: 예전에는 해결 여부 창에서 답을 누르는 순간 통화가 끊겼다. 끝내기와 기록을 나눠, 끊는 결정은 한 번 확인하고 기록은 요약을 보며 차분히 고르게 한다(잘못 고른 답은 저장 전에 바꿀 수 있다).
- **확인**: (1) 연결 후 '종료' → '계속 통화하기' → 통화가 이어지는지 → 다시 '종료' → '통화 끝내기' → 결과 기록에서 '기록하고 끝내기'가 잠겨 있다가 답을 고르면 풀리는지. (2) 고객 없이 '상담 닫기' → '닫기'. (3) 연결 후 고객 폰에서 '통화 종료' → '끝내기' → 엔지니어가 결과 기록 화면인지. 모두 대시보드 '최근 상담'에 보이고, '네'를 골랐을 때만 '원격 해결'인지 본다. 자동 테스트 `e2e/call-end.spec.ts`.
- **제약**: 결과 기록 화면에서 기록하지 않고 화면을 닫으면 세션은 종료되지 않고 링크도 살아 있다(대시보드에 '기록 전'으로 남는다). 저장된 뒤 고객이 링크를 다시 열면 '상담이 이미 끝났어요'가 나온다. 통화 시간은 이 화면을 연 뒤 처음 연결된 때부터 재고, 새로고침하고 다시 연결했다면 그때부터다(결과 기록 화면에 통화 시간이 없을 수 있다). 요약 횟수는 새로 누르거나 방향을 바꾼 횟수·짧게 누름·핀·그린 선을 센다.
- **관련 코드**: `src/app/(engineer)/room/[id]/call-panel.tsx`, `record-view.tsx`, `actions.ts`

### ROOM-13 · 고객 진행 상황 ✅
- **동작**: '고객 기다리는 중' 화면([ROOM-05](#room-05--세션-화면-))의 제목이 지금 기다리는 단계를 말하고, 그 아래 회색 카드에 고객이 어디까지 왔는지 네 줄로 보여 준다(동그라미를 세로선으로 잇는다). 끝난 줄은 초록 체크, 지금 기다리는 줄은 주황 테두리와 굵은 글씨, 아직인 줄은 흐리게.
  1. '문자를 보냈어요' / '카톡을 보냈어요' / '링크를 공유했어요' / '링크를 복사했어요'(어떻게 보냈는지. 고객이 먼저 링크를 열었으면 '링크를 보냈어요')
  2. '고객님이 링크를 열기를 기다리는 중' → '고객님이 링크를 열었어요'
  3. '카메라 허용을 기다리는 중' → '고객님이 카메라를 켰어요'. 카메라가 막히면 빨간 '고객님 카메라가 막혀 있어요'가 되고, 화면 제목도 '고객님 카메라가 막혀 있어요'로 바뀌며 그 아래 빨간 글씨로 원인별로 전화로 해 줄 말이 나온다(막힘: '고객님 화면에 켜는 방법이 나와 있어요. 그대로 따라 해 달라고 말씀해 주세요.', 다른 앱 사용 중, 카메라 없음, 카메라 기능 없는 화면 — [JOIN-05](#join-05--카메라-거부-안내-)와 같은 원인)
  4. '연결되면 바로 영상이 보여요' → '연결하는 중…' → 연결되면 통화 화면으로 바뀐다
- **왜**: 링크를 보낸 뒤 고객이 아무 반응이 없을 때 엔지니어는 "문자를 못 받았나, 카메라에서 막혔나"를 몰라 전화로 처음부터 다시 설명하게 된다. 어디서 멈췄는지 알면 딱 그 단계만 말해 주면 된다.
- **확인**: 링크를 보낸 뒤 고객 폰에서 링크를 열면 몇 초 안에 2번이 체크되는지, 카메라 권한 창에서 '허용 안 함'을 누르면 3번이 빨간 안내로 바뀌는지 본다. 자동 테스트 `e2e/call-end.spec.ts`(링크 열림).
- **제약**: 기다리는 동안 3초마다 서버에 묻는다(`events`의 `link_opened`·`camera_granted`·`camera_denied`, [DATA-01](#data-01--지표-이벤트-목록-)). 그래서 몇 초 늦게 바뀌고, 엔지니어 화면이 가려져 있는 동안에는 묻지 않는다. 이 세션의 예전 기록도 함께 보므로, 이전에 한 번 열었거나 막혔던 세션은 처음부터 그 상태로 보인다(카메라는 가장 최근 기록을 따른다). 문자·카톡 미리보기 방문도 '링크를 열었어요'로 잡힐 수 있다([DATA-02](#data-02--핵심-지표-계산법-)).
- **관련 코드**: `src/app/(engineer)/room/[id]/actions.ts`(`getJoinProgress`), `waiting-view.tsx`, `src/components/ui/step-item.tsx`

### ROOM-14 · 카톡으로 바로 보내기 ✅
- **동작**: 카카오 키가 설정돼 있으면 링크 보내기 화면의 한 줄 맨 앞에 노란 **'카톡 보내기'**(말풍선 아이콘)가 보인다('고객 기다리는 중' 화면에서는 글자 버튼). PC에서도 보인다. 누르면 카톡 친구 선택 화면이 바로 뜨고(PC는 카카오 창에서 카카오 계정으로 로그인한 뒤), 고른 친구에게 '[봐드림] 폰 카메라로 비춰 주세요' 카드(설명 '아래 버튼을 눌러 주세요', 버튼 '카메라 켜기', 링크 포함)가 간다. 공유 창에서 카톡을 한 번 더 고르는 단계가 없다. 카카오링크(Kakao JS SDK `Share.sendDefault`)를 쓰고, SDK는 링크 보내기 화면이 뜰 때 미리 받아 둔다. 누른 뒤에 받기 시작하면 받는 동안 '누름' 효력이 끝나 안드로이드 크롬은 카톡 열기를, PC는 카카오 창을 막을 수 있어서다. 받는 동안(보통 1초 안)은 버튼에 도는 표시가 나오고 눌리지 않는다. 8초가 지나도 못 받으면 실패로 보고 버튼을 다시 풀어 준다. '공유하기'([ROOM-07](#room-07--다른-앱으로-공유-))와는 따로 선다.
- **확인**: 엔지니어 폰·PC에서 '카톡 보내기'를 눌러 친구 선택 화면이 뜨는지, 받은 카드에 '카메라 켜기' 버튼이 있고, 누르면 고객 폰에서 이 상담의 '카메라 켜고 시작하기' 화면으로 가는지 본다. 카드에 버튼이 아예 없거나 사이트 첫 화면으로 가면 아래 '제품 링크 관리' 등록이 빠진 것이다. 카카오 키를 비우면 '카톡 보내기'만 사라지고 문자·공유하기·링크 복사는 그대로인지도 본다. 화면 카탈로그의 '카톡 보내기 → 고객 기다리는 중 (PC)'·'카카오톡을 열지 못했어요'(가짜 SDK).
- **제약**:
  - 받는 사람은 엔지니어의 카톡 친구·채팅방이어야 한다. 그 밖의 고객에게는 [ROOM-06](#room-06--문자로-보내기-)·[07](#room-07--다른-앱으로-공유-)·[08](#room-08--링크-복사-)로 보낸다.
  - 보내는 사람은 **누르는 엔지니어 자신의 카톡 계정**이다. 폰은 그 폰에 로그인된 카카오톡, PC는 뜨는 카카오 창에서 자기 카카오 계정으로 로그인한다. 카카오 개발자 앱의 팀원이 아니어도 되고, 우리 서비스에 카카오 로그인·동의·검수·비즈 앱도 필요 없다(팀원만 되는 제한은 '카카오톡 메시지' API 얘기이고 이 기능과는 다르다). 다만 카카오 계정이 카카오톡과 연결돼 있어야 하고, 폰에 카카오톡이 없으면 아무 일도 일어나지 않는다.
  - 카카오 개발자 앱에 먼저 등록할 것: [앱] > [플랫폼 키] > [JavaScript 키](`NEXT_PUBLIC_KAKAO_JS_KEY`, 공개용)와 그 아래 **JavaScript SDK 도메인**(서비스 주소). 등록하지 않은 주소(미리보기 배포 주소 등)에서는 카카오가 거절한다(오류 4019). 카드 버튼 링크의 도메인은 따로 [앱] > [제품 링크 관리] > [웹 도메인]에도 있어야 한다. 없으면 오류 없이 버튼이 빠진 채 카드만 가거나(등록된 웹 도메인이 하나도 없을 때), 기본 웹 도메인으로 바뀐다. 엔지니어가 여는 주소 그대로(www 유무·포트 포함) 등록한다. 키를 바꾸거나 넣으면 다시 배포해야 반영된다.
  - SDK를 못 받았거나 여는 데 실패하면 버튼 아래에 '카카오톡을 열지 못했어요'와 이 화면에 있는 다른 버튼 이름('문자로 링크 보내기', '공유하기'나 '링크 복사'로 보내 주세요)이 나온다. 다른 방법으로 보내면 이 안내는 사라진다. 예전처럼 공유 창을 대신 열지 않는다. 옆에 '공유하기'가 있고, 카톡 실패를 기다린 뒤 여는 공유 창은 아이폰에서 막힐 수 있어서다. 도메인 미등록처럼 카카오 서버에서 나는 오류는 카카오 쪽 화면(카톡·카카오 창)에만 나오고, 이 화면은 '카톡을 보냈어요'로 넘어간다.
  - 카드를 보냈는지 창을 닫았는지는 알 수 없어서, 친구 선택 창을 여는 데 성공하면 '카톡을 보냈어요'([ROOM-13](#room-13--고객-진행-상황-))로 본다. 전화로 읽어 줄 말도 '카톡으로 링크 보내 드렸어요'로 시작한다([ROOM-05](#room-05--세션-화면-)).
  - 카카오톡 공유에는 앱 하나에 하루 무료 한도가 있다(모든 엔지니어 합계, 카카오 안내로는 3만 건. 카카오 개발자 앱의 쿼터 화면에서 확인할 것). 넘으면 그날은 공유가 막히고, 유료 사용을 켜야 더 보낼 수 있다.
  - 카드 맨 아래 출처에는 카카오 개발자 앱의 앱 이름·아이콘이 나온다(누가 보내든 같다). 카드 이미지(`public/kakao-share.png`)는 카카오 서버가 가져가므로 localhost에서는 이미지가 빠질 수 있다.
  - 고객이 카드 버튼을 누르면 카톡 안 브라우저로 열리므로 자동 전환이 그대로 필요하다 → [JOIN-10](#join-10--카카오톡-앱-안-브라우저-안내-)
  - 고객 이름·연락처는 저장하지 않는다([NFR-07](#nfr-07--고객-연락처는-저장하지-않음-)). 누구에게 보냈는지 기록하지 않는다.
- **현재 상태**: 2026-09-30 제품 담당자가 PC·아이폰에서 카드가 가는 것을 확인했다. 처음에는 운영 카카오 앱에 '제품 링크 관리' 웹 도메인이 없어 '카메라 켜기' 버튼이 빠진 채 왔고, 도메인(`https://bwadrim-nametwo.vercel.app`)을 등록한 뒤 버튼이 생긴 것을 확인했다. 안드로이드 폰은 아직 확인 전이다.
- **관련 코드**: `src/lib/kakao-share.ts`, `src/app/(engineer)/room/[id]/share-buttons.tsx`, `public/kakao-share.png`, 화면 카탈로그의 가짜 SDK `e2e/screens/rig.ts`

## 3. 고객 진입 (JOIN)

### JOIN-01 · 링크만으로 진입 ✅
- **동작**: 고객은 로그인·설치 없이 링크를 누르면 바로 시작 화면을 본다.
- **확인**: 처음 쓰는 폰에서 링크를 열어 로그인 없이 '카메라 켜고 시작하기'가 나오는지 본다.

### JOIN-02 · 시작 화면 ✅
- **동작**: 문자로 링크를 받은 사장님이 처음 보는 화면. 누를 것은 맨 아래 파란 '카메라 켜고 시작하기'(64px, 스크롤해도 아래에 붙어 있음) 하나고, 그 아래 방패 아이콘과 '앱은 안 깔아도 되고, 통화 영상은 남지 않아요'(기사님은 사진만 찍을 수 있다 — [CALL-16](#call-16--사진-찍기-)).
  - 맨 위 로고 '봐드림' — 어디서 온 링크인지 알게
  - 제목 바로 위 한 줄: 파란 원 사람 아이콘과 '**김도현 기사님**이 기다리고 있어요'. 엔지니어 계정에 표시 이름이 있을 때만 보인다([OPS-03](#ops-03--엔지니어-계정-만들기-)).
  - 큰 제목(32px) '고장 난 곳을 폰 카메라로 보여 주세요'
  - 회색 카드에 두 단계(파란 숫자): ① 아래 **'카메라 켜고 시작하기'**를 눌러 주세요 ② 창이 뜨면 **'허용'**을 눌러 주세요(권한 창 그림 — '허용 안 함 | 허용', '허용'에 손가락). 예전 ③ '화살표가 나오면 그쪽으로 폰을 옮겨 주세요'는 뺐다 — 화살표는 통화 중에 '오른쪽으로' 같은 글자와 함께 뜨므로 미리 읽을 필요가 없다([CALL-15](#call-15--방향-지시-방향-링-)).
  - 버튼을 누르면 '카메라 켜는 중…'(도는 표시)으로 바뀌고, 0.4초 뒤 화면이 어두워지며 노란 화살표와 큰 글씨 **''허용'을 눌러 주세요'**가 권한 창이 뜨는 쪽을 가리킨다(아이폰은 가운데 창이라 위쪽 화살표, 안드로이드는 아래쪽 창이라 아래쪽 화살표).
- **왜**: 모르는 링크는 누르지 않으므로 누가 기다리는지를 먼저 보여 준다. 가장 많이 멈추는 곳이 권한 창이라, 창이 뜨기 전에 그림으로 보여 주고 뜬 뒤에는 화살표로 가리킨다.
- **확인**: 링크를 열어 기사님 줄·제목·두 단계·버튼이 한 화면에 보이는지(아이폰 SE 크기 포함 — 375×667 브라우저 화면으로 확인), 버튼을 누르면 어두운 화면과 '허용' 화살표가 뜨는지 본다.
- **제약**: 폰이 다크 모드여도 밝은 화면으로 보인다([NFR-02](#nfr-02--어르신-기준-화면-)). 권한 창 그림과 화살표 위치는 한 가지씩이라 실제 창과 조금 다를 수 있다(아이폰 '허용', 안드로이드 크롬 '사이트 방문 중에 허용'·'이번만 허용' 등, 창 위치도 버전마다 다름). 이미 허용해 둔 폰은 창 없이 바로 켜지는데, 0.4초보다 늦게 켜지면 어두운 화면이 잠깐 보일 수 있다. 기사님 이름은 엔지니어 계정 정보에서 가져오며 고객 정보가 아니다([NFR-07](#nfr-07--고객-연락처는-저장하지-않음-) 무관).
- **관련 코드**: `src/app/join/[token]/start-screen.tsx`, `page.tsx`(기사님 이름), `src/lib/engineer-name.ts`, `src/components/ui/engineer-card.tsx`

### JOIN-03 · 잘못된 링크 안내 ✅
- **동작**: 상황마다 큰 아이콘과 큰 글씨 안내가 나온다(맨 위 '봐드림 원격 A/S'). 누를 버튼 없이 할 일만 알려 준다.
  - 없는 링크(예전 6자리 링크 포함): '열 수 없는 링크예요 / 문자 속 링크를 다시 한 번 눌러 주세요. 그래도 안 열리면 기사님께 새 링크를 받아 주세요.'
  - 종료된 세션: '상담이 이미 끝났어요 / 도움이 더 필요하시면 기사님께 새 링크를 받아 주세요.' 링크를 열어 둔 사이에 세션이 닫혔다면 '카메라 켜고 시작하기'를 누를 때(또는 통화 채널이 입장을 거부할 때, [CALL-12](#call-12--엔지니어-사칭-차단-)) 같은 안내가 나오고 카메라는 꺼진다.
  - 만료된 세션(24시간 지남): '링크가 만료됐어요 / 링크는 24시간만 쓸 수 있어요. 기사님께 새 링크를 받아 주세요.'
  - 서버 오류: '잠깐 연결이 안 돼요 / 조금 있다가 아래 버튼을 눌러 주세요.'와 파란 '다시 열기'(같은 링크를 다시 연다).
- **확인**: 링크 끝 한 글자를 바꿔 열어 본다. 종료한 세션의 링크를 열어 본다.

### JOIN-04 · 카메라 켜기 ✅
- **동작**: '카메라 켜고 시작하기'를 누른 **뒤에만** 카메라·마이크 권한을 묻는다([JOIN-02](#join-02--시작-화면-)의 '허용' 화살표가 뜬다). 뒷면 카메라를 먼저 쓴다. 처리 중에는 버튼이 '카메라 켜는 중…'(도는 표시)으로 바뀌고 잠긴다. 허용하면 더 누를 것 없이 통화 화면으로 간다.
  - **마이크를 못 쓰면 카메라만으로 연결한다.** 기사님과 전화 통화 중이라 마이크가 막혔거나 마이크만 막혀 있으면 카메라만 다시 요청해 연결한다. 기다리는 동안 고객 화면에 '마이크 없이 연결할게요. 말씀은 전화로 나눠 주세요.', 엔지니어 통화 화면에 '고객님 마이크가 꺼져 있어요 / 말씀은 전화로 나눠 주세요'가 뜬다. `camera_granted`에 마이크 여부(`mic`)를 남긴다([DATA-01](#data-01--지표-이벤트-목록-)).
- **왜**: 사장님은 기사님과 전화하면서 링크를 여는 경우가 많다. 마이크 하나 때문에 카메라까지 못 켜면 안 된다.
- **확인**: 링크를 열 때는 권한 창이 안 뜨고, 버튼을 눌러야 뜨는지 본다. 마이크만 실패하는 경우는 자동 테스트(`e2e/call-end.spec.ts`, 가짜 오류)로 확인했다.
- **제약**: 카메라와 마이크를 한 번에 묻는다. 한 번에 실패하면 카메라만 한 번 더 요청하므로, 안드로이드 크롬에서 권한 창을 그냥 닫았다면 카메라 권한 창이 한 번 더 뜰 수 있다. 전화 통화 중인 실제 폰(아이폰·안드로이드)에서 마이크가 어떻게 실패하는지는 아직 실기기로 확인하지 않았다.
- **관련 코드**: `src/app/join/[token]/camera-start.tsx`(`openCamera`)

### JOIN-05 · 카메라 거부 안내 ✅
- **동작**: 카메라를 켜지 못하면 **원인마다 다른 안내**가 나온다(브라우저가 알려 주는 오류 이름으로 나눈다).
  - **막힘**('허용 안 함'을 눌렀거나 설정에서 막힘): '카메라가 꺼져 있어요 / 아래 순서대로 켜 주세요.'와 회색 카드에 폰에 맞는 번호 단계(파란 숫자).
    - 아이폰: ① 주소창 왼쪽의 **가가** 버튼이나 메뉴 버튼 ② **웹 사이트 설정** ③ **카메라**와 **마이크**를 **허용**으로 ④ 아래 **다시 시도하기**. 그래도 안 되면 '폰의 설정 → Safari → 카메라를 허용으로'
    - 안드로이드: ① 주소창 왼쪽의 **자물쇠**나 조절 모양 ② **권한** ③ **카메라**와 **마이크** 켜기 ④ 아래 **새로고침**
    - 그 밖(PC 등): 주소창의 카메라·자물쇠 모양 → 허용 → 새로고침
    - 버튼: 파란 '다시 시도하기'(돌아가는 화살표 아이콘), 회색 '새로고침'
  - **다른 앱이 사용 중**: '다른 앱이 카메라를 쓰고 있어요 / 카메라나 영상통화 앱을 닫고 다시 눌러 주세요.' + '다시 시도하기'
  - **카메라 없음**: '카메라를 찾지 못했어요 / 카메라가 있는 폰에서 문자 속 링크를 열어 주세요.' + '다시 시도하기'
  - **카메라 기능이 없는 화면**(오래된 브라우저, 일부 앱 안 화면): '이 화면에서는 카메라를 켤 수 없어요 / 사파리나 크롬 같은 인터넷 앱으로 링크를 열어 주세요.' + '링크 복사'
  - `camera_denied`에 원인(`reason`, 오류 이름)을 남긴다([DATA-01](#data-01--지표-이벤트-목록-)).
- **확인**: 권한 창에서 '허용 안 함'을 눌러 본다. 아이폰과 안드로이드에서 단계가 맞게 나오는지 본다.
- **제약**: 한 번 '허용 안 함'을 누르면 브라우저가 기억할 수 있어서(특히 안드로이드 크롬), 안내한 설정을 바꾸기 전에는 '다시 시도하기'를 눌러도 권한 창이 다시 안 뜬다. 설정 메뉴의 이름·위치는 OS·브라우저 버전마다 다를 수 있고(아이폰 iOS 18은 '가가' 대신 메뉴 모양), 삼성 인터넷의 메뉴 이름은 아직 실기기로 확인하지 않았다.
- **관련 코드**: `src/app/join/[token]/camera-help.tsx`

### JOIN-06 · 고객 통화 화면 ✅
- **동작**: 내 카메라 화면이 **잘리지 않고 전체**로 나온다(화면 비율이 다르면 위아래나 좌우에 검은 여백이 생긴다). 기사님이 가리키면 빨간 동그라미가 뜨고([CALL-08](#call-08--레이저-포인터-)), 기사님이 핀을 꽂으면 물체에 붙은 핀·화면 밖 화살표·사진 카드가 뜨고([CALL-14](#call-14--물체에-붙는-표시-ar-핀-)), 기사님이 방향 링을 누르는 동안 그쪽 가장자리에 노란 원 화살표와 위쪽 띠에 방향 문구가 뜨고(가까이·멀리는 가운데 노란 네 모서리)([CALL-15](#call-15--방향-지시-방향-링-)), 기사님이 화면을 멈추면 같은 정지 화면과 그림이 보인다([CALL-09](#call-09--프리즈-프레임--드로잉-)). 기사님 목소리가 들린다(기사님 영상은 없음).
  - **위쪽 바**: 사람 아이콘, '김도현 기사님'(이름이 없으면 '기사님'), 그 아래 상태 — 도는 표시와 '기사님을 기다리는 중…' → '기사님과 연결하는 중…' → 초록 점 '기사님이 보고 있어요 · 0:42'(통화 시간). 멈춤 중에는 '화면을 멈추고 설명하고 있어요', 핀이 보이면 '빨간 동그라미를 봐 주세요'.
  - 연결되는 순간 화면 위쪽에 '기사님과 연결됐어요'가 크게 2.5초 뜬다.
  - **기다리는 동안** 화면 가운데 카드: 도는 표시, '기사님을 기다리는 중…', '카메라는 이미 켜졌어요. 고장 난 곳을 미리 비춰 주세요.' 20초 넘게 기다리면 '오래 걸리면 기사님께 전화로 "카메라 켰어요"라고 알려 주세요.'로 바뀐다.
  - **연결이 잠깐 끊기면** 위쪽에 노란 '연결이 잠깐 끊겼어요 / 창을 닫지 말고 기다려 주세요'와 가운데 '다시 연결하는 중…', 상태 점이 노랑. 다시 이어지면 사라진다.
  - **기사님이 화면을 멈추면** 위쪽에 '기사님이 화면을 멈췄어요 / 폰을 내려놓으셔도 돼요'.
  - 아래: 왼쪽 동그란 '카메라 바꾸기'(64px, [JOIN-07](#join-07--카메라-전후면-전환-)), 오른쪽 넓은 빨간 '통화 종료'(64px, [JOIN-08](#join-08--고객이-종료-)).
- **확인**: 고객이 먼저 카메라를 켜고, 엔지니어가 '연결 준비'를 누르면 '기사님이 보고 있어요'와 통화 시간, '기사님과 연결됐어요'가 뜨는지 본다.
- **제약**: '잠깐 끊김'은 브라우저가 연결을 '끊김(disconnected)'으로 판정할 때만 뜬다(보통 몇 초 걸림). 자동 복구(ICE 재시작)는 없고 브라우저가 스스로 되살리는 경우만 돌아온다. 기사님이 오래 안 와도 시간 제한은 없다(20초 뒤 안내만 바뀐다). 음소거·볼륨 버튼이 없다.
- **관련 코드**: `src/app/join/[token]/camera-start.tsx`

### JOIN-07 · 카메라 전/후면 전환 ✅
- **동작**: '카메라 바꾸기'를 누르면 통화를 끊지 않고 앞·뒤 카메라를 바꾼다. 엔지니어 화면도 같이 바뀐다. 기사님과 연결되기 전에 바꿔도, 연결되면 바꾼 카메라가 간다. 기사님이 원격으로 바꿀 수도 있다([CALL-10](#call-10--고객-카메라-원격-전환-)). 전환은 (1) 지금 카메라를 켠 채 새 카메라 열기 → (2) 안 되면 지금 카메라를 끄고 열기 → (3) 그래도 안 되면 원래 카메라로 되돌리기 순서로 시도한다. 실패하면 안내 없이 원래 카메라를 쓴다.
- **확인**: (1) 연결된 상태에서 '카메라 바꾸기' → 엔지니어 화면이 끊김 없이 바뀐다. (2) '기사님을 기다리는 중…'일 때 '카메라 바꾸기' → 엔지니어가 '연결 준비' → 엔지니어 화면에 바꾼 카메라 영상이 나온다.
- **제약**: 카메라 두 개를 동시에 못 여는 폰은 (2)로 넘어가면서 영상이 잠깐(1초 이내) 끊긴다. 바꾸면 손전등은 꺼진다.

### JOIN-08 · 고객이 종료 ✅
- **동작**: 빨간 '통화 종료'를 누르면 아래에서 **'상담을 끝낼까요? / 기사님과 연결이 끊겨요.'** 창이 올라온다. 빨간 '끝내기'를 누르면 끝나고, '계속하기'(맨 아래, 엄지에 가장 가까움)나 창 바깥을 누르면 통화가 그대로 이어진다. 두 버튼 모두 64px. 창이 뜬 직후(0.6초)의 탭은 무시한다.
  - 끝나면 고객 화면은 초록 체크와 **'상담이 끝났어요 / 김도현 기사님과 3분 12초 통화했어요. 이 창은 닫으셔도 돼요.'**로 바뀌고(연결되지 않았으면 '이 창은 닫으셔도 돼요.'만) 카메라·마이크가 꺼진다. 엔지니어 화면은 결과 기록 화면이 된다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).
  - 내가 끝낸 경우에만 아래에 **'잘못 눌렀다면 다시 연결'**이 있다. 누르면 새로고침 없이 카메라를 다시 켜고 이어진다(탭 한 번). 기사님이 끝낸 경우에는 없다.
- **왜**: 사장님은 폰을 들고 비추다가 아래쪽 버튼을 잘못 누르기 쉽다. 디자인 시스템 원칙('종료는 확인 단계를 한 번 거침')과도 맞춘다. 끝난 화면에 통화 시간을 보여 주면 제대로 끝났다는 것을 안심하고 알 수 있다.
- **확인**: '통화 종료' → '계속하기' → 통화 유지. '통화 종료' → '끝내기' → '잘못 눌렀다면 다시 연결' → 다시 연결되는지 본다. 자동 테스트 `e2e/call-end.spec.ts`.
- **제약**: '다시 연결'은 엔지니어가 아직 기록하지 않았을 때만 이어진다. 이미 기록했으면 '상담이 이미 끝났어요'가 나온다. 고객이 종료해도 세션은 엔지니어가 기록해야 '종료'가 된다. 통화 시간은 이 화면에서 처음 연결된 때부터 잰다.

### JOIN-09 · 연결 실패 안내 ✅
- **동작**: 연결이 완전히 실패하면 '연결이 끊겼어요 / 와이파이나 데이터가 켜져 있는지 보고 다시 연결해 주세요.'와 큰 파란 '다시 연결' 버튼이 나온다. 누르면 새로고침 없이 카메라를 다시 켜고 다시 연결한다(탭 한 번).
- **제약**: 자동으로 다시 시도하지 않는다. 실패하면 고객 쪽은 통화 채널에서 나가므로, 엔지니어 화면은 대기 화면('고객님을 다시 기다리고 있어요')으로 바뀐다.

### JOIN-10 · 카카오톡 앱 안 브라우저 안내 ✅
- **동작**: 링크를 메신저·SNS 앱 안 브라우저로 열면 '카메라 켜고 시작하기' 대신 **'이 화면에서는 카메라가 안 켜져요'** 안내가 먼저 나온다(노란 바깥 열기 아이콘, '○○ 안에서 열려서 그래요. 사파리나 크롬으로 열면 돼요.'). 아이폰 카톡 안에서는 카메라가 켜지지 않고 안드로이드도 불안정하기 때문이다.
  - **카카오톡·라인**: 화면이 뜨자마자 **자동으로 폰의 기본 인터넷 앱(사파리·크롬·삼성 인터넷)으로 다시 연다**. 고객이 누를 것은 늘지 않는다. 자동으로 안 넘어가면 파란 '다른 브라우저로 열기'를 누른다. 그 아래 '링크 복사하기'.
  - **네이버·인스타그램·페이스북·밴드·다음 앱**: 자동으로 넘길 방법이 없어서 앱 메뉴 그림(오른쪽 위 ⋯ 버튼이 강조되고, 펼친 메뉴에서 '다른 브라우저로 열기'가 파랗게)과 파란 '링크 복사하기', '복사한 링크를 사파리·크롬·삼성 인터넷 주소창에 붙여 넣어도 돼요.'를 보여 준다.
  - 어느 경우든 아래에 작은 '이대로 계속하기'가 있어 그 자리에서 카메라를 켜 볼 수 있다.
- **확인**: 엔지니어가 '카톡 보내기'(또는 '공유하기' → 카카오톡)로 링크를 카톡에 보낸다. 고객 폰 카톡에서 카드의 '카메라 켜기'나 링크를 누르면 사파리(아이폰)나 기본 인터넷 앱(안드로이드)이 열리고 '카메라 켜고 시작하기' 화면이 나오는지 본다.
- **제약**: 앱을 알아보는 방법은 브라우저가 알려 주는 기기 정보(User-Agent)라서, 앱이 표시를 바꾸면 못 알아볼 수 있다. 카카오톡의 외부 열기는 공식 문서에 없는 방식이라 카톡 업데이트로 막힐 수 있다(그때는 버튼·안내로 대신한다). 자동으로 넘어가면 앱 안과 인터넷 앱에서 `link_opened`가 두 번 기록된다. 메뉴 그림은 한 가지 모양이라 앱마다 버튼 위치(위·아래)와 메뉴 이름('외부 브라우저로 열기' 등)이 조금씩 다르다.
- **관련 코드**: `src/app/join/[token]/open-in-browser.tsx`, `src/lib/in-app-browser.ts`

### JOIN-11 · 다른 곳에서 연결 안내 ✅
- **동작**: 같은 링크를 다른 폰이나 창에서 열어 그쪽이 이어받으면([CALL-13](#call-13--다른-기기에서-이어받기-)) 이 폰은 카메라가 꺼지고 '다른 폰에서 연결됐어요 / 같은 링크가 다른 폰이나 창에서 열렸어요. 이 폰으로 계속하시려면 아래 버튼을 눌러 주세요.'와 큰 '이 폰으로 연결' 버튼이 나온다. 누르면 새로고침 없이 카메라를 다시 켜고 이 폰이 다시 이어받는다(탭 한 번).

### JOIN-12 · 링크 미리보기 문구 🚧
- **동작**: 고객 링크 페이지는 제목 '봐드림 원격 A/S'와 설명 '카메라로 비춰 주시면 기사님이 보면서 알려 드려요. 앱은 안 깔아도 돼요.'를 미리보기 정보(Open Graph)로 내보낸다. 문자·카톡이 링크 미리보기를 만들면 모르는 링크가 아니라 A/S 링크로 보이게 하려는 것이다. 검색엔진에는 올리지 않는다(noindex).
- **확인**: 카톡 대화방에 링크를 보내 미리보기 제목·설명이 보이는지 본다.
- **제약**: 미리보기를 만들지·어떻게 보일지는 앱이 정한다. 아이폰 문자·카카오톡에서 실제로 어떻게 보이는지 아직 실기기로 확인하지 않았다. 미리보기 그림은 없다. 미리보기를 만들려고 앱 서버가 링크를 열면 `link_opened`가 기록될 수 있다([DATA-02](#data-02--핵심-지표-계산법-)).
- **관련 코드**: `src/app/join/[token]/page.tsx`(`metadata`)

## 4. 영상·음성 통화 (CALL)

### CALL-01 · 엔지니어 '연결 준비' ✅
- **동작**: 통화 대기(마이크 켜기 + 통화 채널 입장)는 엔지니어가 **탭한 뒤에만** 시작한다. 보통은 따로 누를 필요가 없다.
  - 대시보드의 '새 A/S 시작'이나 진행 중인 상담의 '이어하기'를 누르는 순간 마이크를 미리 요청해 두고, 세션 화면이 뜨면 그 마이크로 바로 통화 대기를 시작한다. 엔지니어는 곧바로 '고객님께 링크를 보내 주세요' 화면을 본다([ROOM-05](#room-05--세션-화면-)).
  - 세션 화면을 주소로 바로 열었거나 새로고침한 경우에만 '마이크부터 켜 주세요 / 켜면 고객님께 보낼 링크가 나와요'(연결된 적 있으면 '다시 연결할까요? / 고객님 화면이 열려 있으면 바로 이어져요')와 파란 '마이크 켜고 연결 준비'('마이크 켜고 다시 연결')가 나온다. 처리 중에는 '준비 중…'으로 잠긴다.
- **왜**: 예전에는 '새 A/S 시작' 뒤 '마이크 켜고 연결 준비'를 한 번 더 눌러야 했다. 같은 탭에서 마이크를 받아 한 단계를 줄인다(iOS는 탭 없이 마이크를 묻지 않으므로 대시보드 탭을 쓴다).
- **확인**: 대시보드 '새 A/S 시작' → 마이크 허용 → 버튼 없이 '고객님께 링크를 보내 주세요' 화면이 나오고 고객이 들어오면 연결되는지 본다. 세션 화면을 새로고침하면 '마이크 켜고 다시 연결'이 나오는지 본다.
- **제약**: 미리 받은 마이크는 30초 안에 세션 화면이 가져가지 않으면(만들기 실패 등) 끈다. 대시보드에서 누르면 마이크 권한을 세션 화면이 뜨기 전에 묻는다. 같은 세션을 폰과 PC에서 둘 다 통화 대기하면 나중에 시작한 기기가 이어받는다 → [CALL-13](#call-13--다른-기기에서-이어받기-)
- **관련 코드**: `src/lib/webrtc/mic-ahead.ts`, `src/app/(engineer)/dashboard/new-room-button.tsx`·`mic-ahead-link.tsx`, `src/app/(engineer)/room/[id]/call-panel.tsx`

### CALL-02 · 마이크 없이 '보기만' ✅
- **동작**: 엔지니어가 마이크를 거부하거나 마이크가 없어도 영상은 보고, 대기 화면에는 노란 '마이크 꺼짐'(링크 보내기 화면은 문자 그림 아래, 고객 기다리는 중 화면은 진행 상황 카드 오른쪽 위), 통화 화면 영상 위에는 '마이크가 꺼져 있어요 / 고객님은 기사님 목소리를 못 들어요'가 표시된다. 이때 고객은 기사님 목소리를 못 듣는다.
- **제약**: 통화 중에 마이크를 켜고 끌 버튼이 없다. 아이폰에서 마이크를 거부한 채 들어가면 브라우저 자동 재생 제한 때문에 고객 영상이 안 나올 수 있다(실기기 확인 필요). 아이폰 엔지니어는 마이크를 허용하고 쓴다.

### CALL-03 · 자동 연결 ✅
- **동작**: 엔지니어가 '연결 준비'를 누른 상태이고 고객이 카메라를 켰으면, 누가 먼저 들어왔든 추가 조작 없이 연결된다.
- **확인**: 들어오는 순서를 바꿔 두 번 해 본다. 두 번 다 엔지니어 화면에 고객 영상이 떠야 한다.
- **제약**: 시그널링(Supabase Realtime) 연결 자체가 실패하면 안내 없이 대기 문구만 계속 보인다. 권한 거부만은 따로 안내한다([CALL-12](#call-12--엔지니어-사칭-차단-)).

### CALL-04 · 엔지니어 통화 화면 ✅
- **동작**: 고객 쪽에서 연결을 시작하면 **어두운 전체 화면**(통화 화면)으로 바뀌고 '고객님 영상 연결 중…' → 고객 영상 순서로 나온다.
  - 위쪽 바: '원격 A/S · 오늘 오전 10:01'(만든 시각), 그 아래 '통화 중 · 3:12'(처음 연결된 뒤 흐른 시간), 오른쪽 **연결 상태**('● 연결 좋음' 초록 / '● 불안정' 노랑 / '● 연결 중' 노랑, [CALL-07](#call-07--연결-실패-표시-)), TURN 경고 아이콘(있을 때만, 누르면 설명, [NET-03](#net-03--turn-실패해도-통화는-계속--경고-)).
  - 가운데: 고객 영상을 잘리지 않게 전체로, 남는 공간을 모두 써서 크게. 고객 목소리가 들린다.
  - 영상 아래쪽 **'고객 화면'** 알약: 지금 고객 화면에 뜬 방향 지시를 보여 준다('고객 화면 지시 없음' / 노랑 '고객 화면 오른쪽으로' / 멈춤 중 '고객 화면 멈춤', [CALL-15](#call-15--방향-지시-방향-링-)).
  - 아래 도구판(엄지가 닿는 곳): 가운데 방향 링과 그 아래 '− 멀리 | 가까이 +' 알약([CALL-15](#call-15--방향-지시-방향-링-)), 왼쪽 '멈추고 그리기'([CALL-09](#call-09--프리즈-프레임--드로잉-))·'카메라 바꾸기'([CALL-10](#call-10--고객-카메라-원격-전환-)), 오른쪽 '손전등'([CALL-11](#call-11--고객-손전등-원격-켜기-))·빨간 '종료'([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)). 버튼은 60px 동그라미 아래 글자.
  - 처음 쓰기 전까지만 영상 아래 '톡 누르면 빨간 동그라미, 꾹 누르면 핀' 안내가 보인다.
  - 알림(연결 불안정, 화면 멈춤, 마이크 꺼짐, 고객님 마이크 꺼짐 [JOIN-04](#join-04--카메라-켜기-), 고객 쪽 연결 바뀜 [CALL-13](#call-13--다른-기기에서-이어받기-), 화면 멈춤 실패, 카메라 전환 요청·실패)은 영상 위쪽에 띠로 겹쳐 뜬다.
  - 연결이 잠깐 끊기면 영상이 어두워지고 가운데 '다시 연결하는 중…'(도는 표시)이 뜬다. 그동안 방향 링·알약은 흐려진다.
  - PC(가로 1024px 이상)는 위쪽 바에 로고와 빨간 '통화 종료'가 오고, 영상이 왼쪽, 오른쪽 400px 패널에 '방향 지시' 설명·'고객 화면' 알약·도구판·**단축키 안내**(방향키 = 방향 지시, `=`/`-` = 가까이/멀리, F = 멈추고 그리기 / 라이브로)가 온다. F 키로 화면 멈춤을 켜고 끈다.
- **확인**: 연결 후 영상이 화면 대부분을 차지하고, 통화 시간이 1초마다 올라가고, '연결 좋음'이 보이고, 도구판이 스크롤 없이 한 화면에 보이는지 본다(아이폰 SE 크기 포함). PC에서 F를 눌러 멈춤·해제가 되는지 본다.
- **제약**: 작은 폰(아이폰 SE 등)에서는 도구판이 커서 영상이 작아진다. 통화 중에는 링크·공유 버튼이 없다(고객이 나가면 대기 화면에 다시 나온다). 통화 시간은 이 화면을 연 뒤 처음 연결된 때부터 잰다(새로고침하면 다시 0부터). F 키는 확인 창이 떠 있거나 글자를 입력하는 중에는 동작하지 않는다.
- **관련 코드**: `src/app/(engineer)/room/[id]/call-panel.tsx`, `call-ui.tsx`, `src/components/ui/call-control.tsx`, `src/components/guide-pill.tsx`

### CALL-05 · 나갔다 들어오면 재연결 🚧
- **동작**: 한쪽이 새로고침하거나 나가면 남은 쪽은 대기 상태로 돌아간다. 나간 쪽이 다시 들어와 버튼('카메라 켜고 시작하기' 또는 '마이크 켜고 다시 연결')을 누르면 남은 쪽은 아무것도 안 해도 다시 연결된다.
- **확인**: 연결 중에 고객 폰을 새로고침하고 '카메라 켜고 시작하기'를 다시 눌러 본다.
- **제약**: 알아차리는 데 몇 초 걸릴 수 있다. 새로 들어온 쪽이 이어받으므로([CALL-13](#call-13--다른-기기에서-이어받기-)), 나간 쪽의 이전 연결이 아직 채널에 남아 있어도 새로 들어오면 바로 다시 연결된다(모의 테스트로 확인). 이때 엔지니어 화면에 '고객 쪽 기기가 바뀌었어요'가 잠깐 뜰 수 있다. 종료한 쪽은 다시 연결되지 않는다(끝난 화면이 되살아나지 않음).

### CALL-06 · 엔지니어가 종료 ✅
- **동작**: 엔지니어가 '종료' → '통화 끝내기'를 누르면([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)) 고객 화면이 바로 '상담이 끝났어요'로 바뀌고 고객 카메라가 꺼진다. 엔지니어 마이크도 꺼지고 결과 기록 화면으로 간다. 확인 창을 연 채로는 통화가 이어진다.

### CALL-07 · 연결 실패 표시 ✅
- **동작**:
  - **잠깐 끊김**: 연결된 뒤 브라우저가 연결을 '끊김'으로 판정하면 엔지니어 화면 위쪽 상태가 노란 '● 불안정'이 되고, 영상 위에 '연결이 불안정해요 / 다시 연결하고 있어요' 띠와 '다시 연결하는 중…'이 뜬다(방향 지시는 잠김). 고객 화면은 [JOIN-06](#join-06--고객-통화-화면-)의 '연결이 잠깐 끊겼어요'. 다시 이어지면 '● 연결 좋음'으로 돌아온다.
  - **완전 실패**: 엔지니어 화면이 빨간 상태 동그라미와 제목 '연결에 실패했어요', 빨간 글씨 '고객님께 링크를 다시 열어 달라고 말씀해 주세요.', 고객 진행 상황과 다시 보내는 버튼(폰은 '문자 다시 보내기', 그 아래 카톡 보내기·공유하기·링크 복사 중 이 기기에서 되는 것), 오른쪽 위 끝내는 버튼('통화 종료' 또는 '상담 닫기', [ROOM-10](#room-10--종료와-출장-없이-해결-입력-))으로 바뀐다. 고객 화면은 [JOIN-09](#join-09--연결-실패-안내-)와 같다.
  - 고객이 나가면 엔지니어 화면은 대기 화면('고객님을 다시 기다리고 있어요')으로 바뀌고, 고객이 다시 들어오면 자동으로 연결된다.
- **제약**: 판정은 브라우저가 한다 — '끊김'은 보통 몇 초, '완전 실패'는 수십 초 걸릴 수 있다. 자동 복구(ICE 재시작)는 없어서, 브라우저가 스스로 되살리지 못하면 '완전 실패'가 된다. 화질·지연을 재서 '불안정'을 판단하지는 않는다(끊김 여부만).
- **관련 코드**: `src/lib/webrtc/call.ts`(`onQuality`), `src/app/(engineer)/room/[id]/call-panel.tsx`, `call-ui.tsx`(`QualityPill`)

### CALL-08 · 레이저 포인터 ✅
- **동작**: 연결된 뒤 엔지니어가 영상을 **짧게 누르면**(0.5초 미만) 고객 화면의 같은 위치에 **빨간 동그라미**(가운데가 비어 버튼을 가리지 않음, 두근거리는 효과)가 나타나고 **3초 뒤 서서히 사라진다**. 새로 누르면 이전 것을 바로 대체한다. 엔지니어 화면에도 같은 동그라미가 떠서 고객에게 어디가 보이는지 알 수 있다. 동그라미는 손가락을 뗄 때 뜬다(길게 누르기와 구분하기 위해). 처음 쓰기 전까지 영상 아래에 '톡 누르면 빨간 동그라미, 꾹 누르면 핀' 안내가 있다([CALL-04](#call-04--엔지니어-통화-화면-)). 누른 횟수는 결과 기록 요약의 '가리키기·그리기'에 들어간다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).
- **확인**: 연결 후 엔지니어가 영상의 네 모서리 근처와 가운데를 차례로 눌러 본다. 고객 화면에서 같은 곳에 동그라미가 뜨고 3초 뒤 사라지는지, 모서리를 눌러도 고객 화면에서 잘리지 않는지 본다.
- **제약**: 동그라미는 화면 위치에 붙어 있어서, 고객이 폰을 움직이면 가리킨 물체에서 벗어난다(그래서 3초만 보여 준다). 정확히 가리켜야 하면 폰을 잠시 고정해 달라고 말로 안내한다. 영상 밖 검은 여백을 누르면 무시한다. 누른 채 손가락을 12px 넘게 움직이면 아무것도 하지 않는다. 오래 누르면 동그라미 대신 [CALL-14](#call-14--물체에-붙는-표시-ar-핀-) 핀이 된다. 고객은 가리킬 수 없다(보기만). 앞면 카메라로 바꿔도 좌우가 뒤집혀 보이지 않으므로 위치는 그대로 맞는다.

### CALL-09 · 프리즈 프레임 + 드로잉 ✅
- **동작**: 연결된 뒤 엔지니어가 도구판의 '멈추고 그리기'(PC는 F 키)를 누르면 **엔지니어가 보던 장면이 사진으로 떠져** 두 화면에 똑같은 정지 화면이 뜬다. 엔지니어가 손가락으로 그리면 빨간 선(흰 테두리)이 실시간으로 고객 화면에도 그려진다. 멈춘 동안 도구판은 이렇게 바뀐다: 가운데 방향 링·알약 자리에 **파란 '라이브로'**(멈춤 해제, 선도 사라짐, PC는 F 키)와 '멈춘 화면에서는 방향을 알려 줄 수 없어요', 왼쪽 '되돌리기'(마지막 선 지우기)·'모두 지우기'(선 전부 지우기, 선이 없으면 흐림), 오른쪽 '종료'. 영상 위에 '화면을 멈췄어요 / 손가락으로 그리면 고객님 화면에도 그려져요'가 뜬다. 고객 화면 위쪽 상태는 '화면을 멈추고 설명 중이에요', 그 아래 '기사님이 화면을 멈췄어요 / 폰을 내려놓으셔도 돼요'. 멈춘 동안 고객 카메라 영상은 뒤에서 계속 전송된다.
- **왜**: 멈춘 동안 지금 누를 것은 '라이브로' 하나라 파랑으로 둔다. 고객은 멈춘 동안 폰을 들고 있을 필요가 없다.
- **확인**: 연결 후 '멈추고 그리기' → 고객 폰에도 같은 장면이 멈춰 보이는지, 그린 선이 같은 자리에 나타나는지, 되돌리기·모두 지우기·라이브로가 고객 화면에도 반영되는지 본다. 고객이 폰을 움직여도 멈춘 화면과 선은 그대로여야 한다. 자동 테스트 `e2e/call-guide.spec.ts`(라이브로).
- **제약**: 정지 화면은 연결(데이터 채널)로만 보낼 수 있어서, 연결이 불안정하면 영상 위에 '연결이 불안정해 화면을 멈추지 못했어요. 다시 눌러 주세요.'가 나온다. 사진은 긴 변 1280px JPEG로 줄여 보낸다(보통 수십~수백 KB). 연결이 끊기면 양쪽 모두 멈춤이 풀린다. 멈춘 동안에는 레이저 포인터 대신 그리기만 되고, 카메라 바꾸기·손전등·방향 지시는 숨는다. 고객은 그릴 수 없다. 색·굵기 선택, 도형·글자 도구는 없다.

### CALL-10 · 고객 카메라 원격 전환 ✅
- **동작**: 연결된 뒤 엔지니어가 도구판의 '카메라 바꾸기'를 누르면 고객 폰의 앞·뒤 카메라가 바뀐다([JOIN-07](#join-07--카메라-전후면-전환-)과 같은 방식). 고객 화면에는 '기사님이 앞(뒤) 카메라로 바꿨어요'가 크게 2.5초 뜬다. 결과가 올 때까지 버튼은 잠긴다(최대 6초). 지금 어느 카메라인지는 영상으로 보인다(따로 글자 표시는 없다).
- **확인**: 연결 후 엔지니어가 '카메라 바꾸기'를 누른다. 영상이 앞 카메라(고객 얼굴)로 바뀌고, 고객 폰에 안내 문구가 뜨는지 본다. 아이폰과 안드로이드 고객 모두 해 본다.
- **실기기 확인**: 2026-09-24 엔지니어 PC ↔ 고객 아이폰에서 원격 전환이 고객 탭 없이 바로 됨.
- **제약**: 폰이 고객의 탭 없이 카메라를 못 바꾸게 막으면(확인한 아이폰에서는 막히지 않았지만 기종·버전에 따라 생길 수 있음) 고객 화면에 '기사님이 카메라를 바꿔 달라고 하셨어요'와 파란 '카메라 바꾸기' 버튼이 뜨고, 엔지니어 영상 위에는 '고객님께 화면의 '카메라 바꾸기'를 눌러 달라고 말씀해 주세요'가 뜬다. 전환에 실패하면 '고객 폰에서 바꾸지 못했어요'가 뜬다. 멈춘 화면([CALL-09](#call-09--프리즈-프레임--드로잉-))에서는 이 자리에 '되돌리기'가 온다.

### CALL-11 · 고객 손전등 원격 켜기 ✅
- **동작**: 도구판에 늘 '손전등' 자리가 있다. 고객 폰 카메라가 손전등을 지원하면 누를 수 있고, 누를 때마다 고객 폰 손전등이 켜지고 꺼진다(켜져 있으면 동그라미가 흰색으로 바뀌고 '손전등 끄기'). 지원하지 않으면 흐린 '손전등 없음', 고객 카메라 상태를 받기 전에는 흐린 '손전등'이다. 고객 화면에는 '기사님이 손전등을 켰어요(껐어요)'가 뜬다. 통화가 끝나면 카메라와 함께 꺼진다.
- **확인**: 안드로이드 고객 폰(뒤 카메라)으로 연결한 뒤 엔지니어 화면의 '손전등'이 눌리는지, 누르면 고객 폰 플래시가 켜지고 영상이 밝아지는지 본다. 아이폰 고객 폰에서도 본다.
- **실기기 확인**: 2026-09-24 엔지니어 PC ↔ 고객 아이폰에서 손전등 켜기·끄기가 됨.
- **제약**: 지원 여부는 고객 폰 브라우저가 알려 주는 대로 판단한다. 확인한 아이폰은 되지만 오래된 iOS에서는 안 될 수 있다(그때는 '손전등 없음'). 안드로이드 고객 폰은 아직 확인하지 않았다. 앞 카메라에는 손전등이 없어서, 카메라를 바꾸면 '손전등 없음'이 되거나 꺼진다. 멈춘 화면에서는 이 자리가 비어 있다(오른쪽에는 '종료'만).

### CALL-12 · 엔지니어 사칭 차단 ✅
- **동작**: 통화 신호 채널을 방마다 일방통행 두 개로 나눈 **비공개 채널**로 쓴다.
  - **엔지니어 → 고객** 채널에 신호(응답·포인터·원격 카메라 명령·종료)를 보낼 수 있는 건 **로그인한 그 세션의 주인뿐**이다. 채널에 들어올 때 Supabase 서버가 로그인 토큰(JWT)의 사용자와 세션 주인을 DB 규칙으로 대조한다(메시지마다가 아니라 입장·토큰 갱신 때 확인하고 그 결과를 쓴다). 영상·음성·포인터·그리기는 이 채널이 아니라 암호화된 P2P 연결로 오가므로 JWT 확인과 무관하다. 고객 폰은 이 채널에서 온 신호만 믿는다. 그래서 링크를 가진 제3자나 다른 엔지니어 계정은 엔지니어 행세를 해 고객 카메라를 보거나 통화를 끊을 수 없다.
  - **고객 → 엔지니어** 채널은 링크를 연 사람 누구나 보낼 수 있다(고객은 로그인이 없으므로).
  - 두 채널 모두 종료·만료된 세션이면 새로 들어올 수 없다.
  - 들어가기 전에 로그인 토큰을 먼저 싣고, 보내기가 거부되면 토큰을 다시 싣고 한 번 더 시도한다. 페이지를 막 연 직후 토큰이 늦게 붙어 로그인한 엔지니어가 익명으로 취급되던 문제를 막기 위해서다.
  - 채널이 거부하면 엔지니어 화면에 '통화 권한을 확인하지 못했어요 / 로그인이 풀렸을 수 있어요'와 '다시 로그인' 버튼이, 고객 화면에 '상담이 이미 끝났어요'가 나온다.
- **확인**: [OPS-04](#ops-04--db-준비-)와 [OPS-05](#ops-05--realtime-공개-채널-끄기-)를 적용한 뒤 평소처럼 통화가 되는지 본다.
- **제약**:
  - 운영 확인(2026-09-24): 공개 채널을 끈 상태에서 로그인 없는 고객과 로그인한 엔지니어의 통화가 정상. 사칭 거부는 로컬 Postgres에 같은 규칙을 넣은 검사와 모의 테스트로 확인했다(운영에서 직접 공격해 보지는 않음).
  - 링크를 가진 사람은 여전히 **고객으로** 들어올 수 있다. 이때 보이는 건 그 사람 자신의 카메라뿐이지만 진짜 고객 대신 연결될 수는 있다. 그러면 엔지니어 화면에 '고객 쪽 기기가 바뀌었어요'가 뜬다 → [CALL-13](#call-13--다른-기기에서-이어받기-)
  - 링크를 가진 사람은 엔지니어 쪽 신호를 엿들을 수 있다(엔지니어 폰의 네트워크 주소가 보임, 영상·음성은 안 보임).
  - 이미 들어와 있던 연결이 세션 종료 순간 서버에서 끊기는지는 확인하지 않았다(종료 시 양쪽 화면은 스스로 채널을 나간다).
- **관련 코드**: `src/lib/webrtc/call.ts`, `supabase/schema.sql`(맨 아래 채널 규칙)

### CALL-13 · 다른 기기에서 이어받기 ✅
- **동작**: 같은 역할(엔지니어 또는 고객)이 두 기기(또는 두 창)에서 들어오면 **가장 늦게 들어온 기기가 이어받는다**. 상대 쪽은 아무것도 안 해도 새 기기와 다시 연결된다.
  - 엔지니어: 폰에서 통화하다가 PC에서 '연결 준비'를 누르면 PC로 넘어간다. 폰 화면은 '다른 기기에서 이어받았어요'와 '여기서 다시 받기'·'상담 목록으로'로 바뀌고 마이크가 꺼진다(해결 여부 질문이 떠 있었어도 이 화면으로 바뀐다). '여기서 다시 받기'를 누르면 다시 폰으로 온다.
  - 고객: 같은 링크를 다른 폰에서 열고 '카메라 켜고 시작하기'를 누르면 그 폰으로 넘어간다. 먼저 쓰던 폰은 '다른 폰에서 연결됐어요'와 '이 폰으로 연결' 버튼으로 바뀌고 카메라가 꺼진다([JOIN-11](#join-11--다른-곳에서-연결-안내-)).
  - 고객 쪽 기기가 바뀌면 엔지니어 화면에 8초 동안 '고객 쪽 기기가 바뀌었어요 / 고객님이 새로고침했거나 다른 기기로 들어왔어요. 모르는 사람이면 통화를 끝내세요.'가 뜬다. 링크가 새어 다른 사람이 들어온 경우를 알아채기 위해서다.
  - 밀려난 기기는 종료 신호를 보내지 않는다. 그래서 상대 화면이 '끝났습니다'로 바뀌지 않는다.
- **확인**: 엔지니어 폰으로 연결한 뒤 PC에서 같은 세션의 '연결 준비'를 누른다. PC에 고객 영상이 나오고 폰은 '다른 기기에서 이어받았어요'가 되는지 본다. 고객 링크를 두 번째 폰에서 열어 같은 방식으로 본다.
- **제약**: '늦게 들어온' 순서는 서버 시각으로 맞춘 기기 시각으로 정한다. 1초 안에 두 기기가 동시에 들어오면 어느 쪽이 남을지는 정해져 있지 않다(둘 중 하나만 남는 것은 보장). 고객이 새로고침해도 알림이 뜰 수 있다. 실기기로는 아직 확인하지 않았다(모의 테스트로 확인).
- **관련 코드**: `src/lib/webrtc/call.ts`(기기 id, presence, 신호의 from/to)

### CALL-14 · 물체에 붙는 표시 (AR 핀) 🚧
- **동작**: 연결된 뒤 엔지니어가 영상을 **길게 누르면**(0.5초) 그 자리에 빨간 핀이 꽂히고, 고객이 폰을 움직여도 **핀이 화면 위치가 아니라 실제 물체 위에 붙어 따라간다**([CALL-08](#call-08--레이저-포인터-)은 짧게 누름, 화면 위치에 3초). 누르는 동안 손가락 둘레에 흰 원이 차오르고, 다 차면 핀이 꽂힌다(진동 지원 폰은 짧게 진동).
  - 누른 순간의 장면을 기준 사진으로 잡고, 엔지니어 폰과 고객 폰이 **각자** 자기 영상에서 그 사진을 찾아 따라간다(네트워크 지연과 무관). 기준 사진은 통화 연결(전용 DataChannel `anchor`)로 한 번 보낸다.
  - 확신이 없으면 핀을 숨긴다 — 옆 LAN 포트·옆 차단기처럼 틀린 곳을 가리키는 것보다 안 보이는 게 낫기 때문.
  - 고객 화면: 핀이 보이면 위쪽 문구가 '빨간 동그라미를 봐 주세요'. 핀 자리가 화면 밖이면 가장자리 빨간 화살표 + 큰 글씨 '화살표 쪽으로 폰을 돌려 주세요'. 0.8초 넘게 못 찾거나 무늬가 적어 찾을 수 없으면 기사님이 표시한 사진 카드 + '기사님이 표시한 곳을 비춰 주세요'. 카드·화살표가 뜨면 상태 문구는 숨긴다. 고객은 아무것도 누르지 않는다.
  - 엔지니어 화면: 영상 왼쪽 위에 고객 화면 상태('고객 화면에 표시 중' / '고객 화면에서 찾는 중…' / '고객 화면에서 놓침' / '고객 화면 밖이라 화살표로 안내 중' / '고객에게 사진 카드로 안내 중'), 무늬가 적거나 반복되면 4초 안내, 오른쪽 위에 '핀 지우기'. 새로 길게 누르면 이전 핀을 대체한다(지금 붙어 있는 핀의 영역 안을 누르면 핀이 추가된다).
  - 화면 멈춤([CALL-09](#call-09--프리즈-프레임--드로잉-)) 중에는 길게 누르기가 되지 않고 핀도 가려진다(멈춤을 풀면 다시 보인다).
- **확인**: 연결 후 엔지니어가 보일러 조절기·공유기 뒷면·명판처럼 평평하고 글자·무늬가 있는 곳을 길게 누른다. 고객 폰에서 같은 자리에 핀이 뜨고, 고객이 폰을 천천히 옮기고 기울이고 가까이 가도 핀이 그 자리에 붙어 있는지, 화면 밖으로 뺐다가 다시 비추면 돌아오는지, 틀린 곳에 붙지 않는지 본다. '핀 지우기'를 누르면 양쪽에서 사라지는지 본다. 짧게 누르면 예전처럼 3초 동그라미인지도 본다.
- **제약**:
  - **실기기로는 아직 확인하지 않았다.** 합성 영상 벤치마크와 가짜 카메라 자동 테스트(실제 통화 화면 두 개를 이어 길게 누르기 → 고객 화면 핀·지우기)로만 확인했다. 2026-09-26 아이폰 15 Pro Max Safari 시험(당시 실험실 페이지)에서 좌우로 움직이거나 가까이 가면 놓쳤다. 이후 탭 주변을 좁게 보도록(짧은 변의 50% → 30%) 하고 4배 확대 제한을 16배로 풀었다 — 합성 실험에서는 3cm 돌출 물체 좌우 이동 표시율 39% → 100%, 가까이 가기 4배 → 8배 이상.
  - 평평한 면만 대상이다(SLAM 아님). 무늬 없는 면·똑같은 무늬가 반복되는 곳(포트 줄, 차단기 줄)은 사진 카드로 안내한다. 튀어나온 버튼 등 입체 부분은 보는 각도에 따라 조금 어긋나거나 숨을 수 있다.
  - 폰을 세로↔가로로 돌리면 핀을 놓치고 다시 찾는다(돌린 각도가 크면 못 찾을 수 있음). 아이폰 Pro는 약 20cm보다 가까우면 초점이 안 맞아 놓칠 수 있다. 아주 빠르게 흔들면(초당 60cm 이상) 숨는다.
  - 선 긋기는 없다(선은 [CALL-09](#call-09--프리즈-프레임--드로잉-)). 고객은 핀을 만들 수 없다.
  - 엔지니어가 [CALL-15](#call-15--방향-지시-방향-링-) 방향 링·알약을 누르고 있는 동안에는 고객 화면의 핀·화면 밖 화살표·사진 카드를 잠시 숨긴다(추적은 계속, 떼면 돌아온다).
  - 영상·사진은 두 폰 안에서만 처리하고 서버로 보내거나 저장하지 않는다(기준 사진은 P2P 연결로만 오간다).
- **관련 코드**: `src/lib/tracking/`(설계: `src/lib/tracking/README.md`), `src/components/anchor/`(통화 화면 층, 길게 누르기 원), `src/components/anchor-overlay.tsx`, `src/lib/webrtc/call.ts`(`anchor` 채널), `src/lib/webrtc/data-link.ts`, `src/app/(engineer)/room/[id]/call-panel.tsx`(짧게/길게 판정), `src/app/join/[token]/camera-start.tsx`, 벤치마크 `scripts/tracking-bench/`, 자동 테스트 `e2e/call-anchor.spec.ts`

### CALL-15 · 방향 지시 (방향 링) 🚧
- **동작**: 연결된 뒤 엔지니어가 도구판 가운데 **방향 링**이나 그 아래 **'− 멀리 | 가까이 +' 알약**을 **누르고 있는 동안만** 고객 화면에 지시가 뜨고, 손을 떼면 사라진다. 사라지는 것이 곧 '멈추세요' 신호다.
  - **방향 링**(지름 160px): 둥근 판 하나를 상하좌우 네 조각으로 나눴다(조각 사이 4px 틈, 흰 꺾쇠). 가운데 구멍(지름 54px)은 엄지를 쉬는 '멈춤' 자리다. 누른 조각이 노랗게 채워진다.
  - **가까이·멀리 알약**(160×48px, 링 8px 아래): 왼쪽 반 '− 멀리', 오른쪽 반 '가까이 +'. 누른 쪽이 노랗게 채워진다. 예전에는 십자키 가운데 원을 위(+)·아래(−)로 나눴는데, 방향과 섞여 헷갈려 링 밖으로 뺐다.
  - 고객 화면(방향): 위에 검은 띠 — 노란 동그라미 안 화살표 + 큰 글씨 '오른쪽으로', 아래 줄 '휴대폰을 천천히 옮겨 주세요'(위·아래는 '화살표 쪽으로 천천히 옮겨 주세요'). 그리고 그쪽 가장자리에 **노란 원(약 100px) 안 검은 화살표**가 들어오며 그 방향으로 살짝 밀렸다 돌아오기를 반복한다. 원은 얇은 어두운 테두리와 그림자가 있어 흰 벽에서도 보인다. 좌우는 화면 세로 가운데, 위는 띠 바로 아래, 아래는 통화 종료 버튼 위. 화면 가운데는 비워 비추는 물건을 가리지 않는다.
  - 고객 화면(가까이·멀리): 띠에 '+ 가까이 / 휴대폰을 천천히 앞으로 내밀어 주세요' 또는 '− 멀리 / 휴대폰을 천천히 뒤로 빼 주세요', 화면 가운데 노란 네 모서리 — 가까이는 바깥을 향한 모서리(┌ ┐ └ ┘)가 벌어지고, 멀리는 안쪽을 향한 모서리(┘ └ ┐ ┌)가 모인다. 움직임 없이 멈춘 그림만 봐도 뜻이 다르게 보인다.
  - 누른 채 엄지를 굴리면 떼지 않고 방향이 바뀐다(대각선 근처에서는 10° 여유를 두어 깜빡이지 않는다). 가운데 구멍으로 오면 꺼진다. 누른 채 링 밖으로 넘쳐도 각도로 판정해 끊기지 않는다. 알약에서도 누른 채 옆으로 밀면 멀리↔가까이가 바뀐다.
  - 링에서 시작한 누름은 방향만, 알약에서 시작한 누름은 가까이·멀리만 보낸다. 링과 알약 사이 틈, 링 상자의 빈 모서리는 눌러도 아무것도 하지 않는다. 알약 가운데 경계(±10px)를 처음 누르면 손가락이 한쪽으로 옮겨 갈 때까지 보내지 않는다(아래 조각을 누르다 미끄러진 손가락이 가까이·멀리를 띄우지 않게).
  - 가운데 구멍이나 알약 경계를 톡 누르기만 하면 아무것도 보내지 않고, '고객 화면' 알약 자리에 '방향을 누르고 있는 동안만 고객 화면에 보여요'(알약이면 '멀리나 가까이 한쪽을 꾹 누르고 있어 주세요')가 1.8초 뜬다.
  - 안드로이드 폰에서 손가락으로 누르면 방향이나 가까이·멀리가 켜지거나 바뀔 때 아주 짧게 떨린다(화면을 안 보고도 알 수 있게. 아이폰은 떨림 기능이 없고, 키보드·마우스는 떨리지 않는다).
  - 톡 짧게 눌러도 고객 화면에는 1초 동안 보인다. 1초 안에 같은 방향을 다시 누르면 그때부터 다시 1초를 보장한다.
  - PC는 방향키, `=`(가까이), `-`(멀리)를 누르고 있는 동안. 마우스를 올리면 누를 자리가 조금 밝아진다.
  - 전용 통화 연결(DataChannel `guide`)로 보낸다. 누르는 동안 0.4초마다 신호를 다시 보내고, 고객 폰은 1.5초 동안 신호가 없으면 스스로 지운다(연결이 끊겨도 화살표가 남지 않게). 엔지니어 창이 가려지거나 포커스를 잃으면 손을 뗀 것으로 본다. 연결이 끊기거나 다시 이어지면 고객 화면의 지시는 바로 지운다.
  - 화면 멈춤([CALL-09](#call-09--프리즈-프레임--드로잉-)) 중에는 링·알약 자리(160×216px)에 파란 '라이브로'와 '멈춘 화면에서는 방향을 알려 줄 수 없어요'가 온다. 자리 크기가 같고, 멈춘 동안 숨는 손전등 자리도 비워 두며 도구 이름 높이를 두 줄로 맞춰 옆 버튼이 움직이지 않는다. 고객 영상이 연결되기 전과 연결이 잠깐 끊긴 동안([CALL-07](#call-07--연결-실패-표시-))에는 링·알약이 흐리고(40%) 눌러도 보내지 않는다.
  - 엔지니어 화면의 '고객 화면' 알약([CALL-04](#call-04--엔지니어-통화-화면-))이 지금 고객에게 보내고 있는 지시를 노랗게 보여 준다('고객 화면 → 오른쪽으로').
  - 고객 화면에 방향 지시가 떠 있는 동안은 AR 핀·화면 밖 화살표·사진 카드([CALL-14](#call-14--물체에-붙는-표시-ar-핀-))와 위쪽 상태 문구를 잠시 숨긴다(추적은 계속). 떼면 바로 돌아온다. 엔지니어가 지금 직접 하는 지시가 자동 안내보다 먼저이고, 화살표 두 개가 동시에 떠 헷갈리지 않게 하기 위해서다.
  - 움직임을 줄이는 설정(접근성 '동작 줄이기')을 켠 폰에서는 원이 밀리지 않고 모서리도 움직이지 않는다(모양은 그대로).
  - (선택) 손을 뗀 뒤 1.2초 동안 노란 테두리와 '그대로요 / 잠깐 멈춰 주세요'. 통화 화면에서는 아직 켜지 않았다(실험실에서만).
- **왜**: 예전 십자키는 네 조각이 따로 떨어진 타일과 겹친 가운데 원(+가까이/−멀리)이 섞여 지저분했고, 고객 화살표는 검은 테두리 셰브론 3개라 무거웠다. 디자이너 네 방향 시안을 엔지니어 조작·고객 가독성·디자인 완성도로 비교해 골랐다(2026-09-28).
- **확인**: 연결 후 엔지니어가 링 오른쪽 조각을 누르고 있는다. 고객 폰 오른쪽 가장자리에 노란 원 화살표와 '오른쪽으로'가 뜨고, 누르는 동안 계속 있다가 떼면 사라지는지 본다. 누른 채 위로 굴리면 '위쪽으로'로 바뀌는지, 알약 오른쪽을 누르면 '가까이'(모서리가 벌어짐), 누른 채 왼쪽으로 밀면 '멀리'(모서리가 모임)인지, 가운데 구멍을 톡 누르면 쓰는 법이 뜨는지, PC에서 방향키를 누르고 있는 동안 뜨는지, '멈추고 그리기' 중에는 링 대신 '라이브로'가 나오는지 본다. AR 핀을 꽂은 뒤 링을 누르면 핀이 잠시 숨었다가 떼면 돌아오는지도 본다. 흰 벽을 비추는 고객 폰에서도 원 화살표가 잘 보이는지 본다. 통화 없이 한 화면에서 흉내 내 보려면 실험실 `/lab/guide`(지연·끊김 흉내)를 쓴다.
- **제약**:
  - **실기기로는 아직 확인하지 않았다.** 가짜 카메라 자동 테스트(실제 통화 화면 두 개를 잇고 누르기·굴리기·톡·가까이→멀리 밀기·구멍 톡 안내·방향키·AR 핀 잠시 숨김·멈춤 중 비활성·`guide_used` 기록)와 누른 자리 판정 단위 테스트(`src/components/guide-pad-geometry.test.ts`)로만 확인했다.
  - 방향은 고객이 보는 화면 기준이라, 고객이 폰을 가로로 돌리거나 앞 카메라로 바꾸면 보정이 없다.
  - 고객 화면의 위·아래 원은 영상 비율을 따지지 않고 띠 아래·통화 종료 버튼 위에 둔다. 세로 영상(폰 뒤 카메라 보통)이면 영상 위·아래 가장자리에 조금 걸친다.
  - 새 코드가 배포되기 전에 열어 둔 고객 화면은 `guide` 연결이 없어 지시가 뜨지 않는다(새로고침하면 된다).
  - 통계 화면([DATA-06](#data-06--통계-화면-))에는 아직 나오지 않는다(`guide_used`는 기록만 한다). 누른 횟수는 결과 기록 요약의 '방향 지시'로 보인다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).
  - `/lab/guide`는 로그인 없이 열리는 공개 페이지다(검색 노출 막음, 로그인 확인 `src/proxy.ts`에서 `/lab/*` 제외).
- **관련 코드**: `src/lib/webrtc/guide.ts`, `src/lib/webrtc/call.ts`(`guide` 채널), `src/components/guide-dpad.tsx`(링·알약), `src/components/guide-pad-geometry.ts`(모양·누른 자리 판정), `src/components/guide-overlay.tsx`(고객 화면), `src/components/guide-pill.tsx`, `src/components/guide.module.css`, `src/app/(engineer)/room/[id]/call-panel.tsx`, `src/app/join/[token]/camera-start.tsx`, `src/app/lab/guide/`, 자동 테스트 `e2e/call-guide.spec.ts`

### CALL-16 · 사진 찍기 🚧
- **동작**: 연결된 뒤 엔지니어 통화 화면의 영상 오른쪽 아래 **흰 카메라 버튼**(56px)을 누르면, 고객 폰이 **자기 카메라로 사진을 찍어** 엔지니어 폰으로 보낸다. 영상(망 상태에 따라 흐려짐)을 캡처하는 게 아니라 고객 폰 안에서 찍으므로 명판·에러 코드 글자가 더 선명하다.
  - 누르면 영상이 잠깐 하얗게 번쩍이고, 받는 동안 버튼에 도는 표시. 받으면 영상 위에 초록 '사진 N장 찍었어요 / 통화를 끝낼 때 저장할 수 있어요'(2초), 버튼 오른쪽 위에 지금까지 찍은 장수. 못 받으면 빨간 '사진을 받지 못했어요. 다시 눌러 주세요.'
  - **고객 화면**에는 찍을 때마다 '기사님이 사진을 찍었어요'가 크게 2.5초 뜬다(몰래 찍히지 않게). 고객은 누를 것이 없다.
  - 찍는 방법(고객 폰): ① 사진 촬영 기능(ImageCapture, 안드로이드 크롬 등)이 있으면 카메라 원본으로 ② 없으면(아이폰 등) 찍는 순간만 카메라 해상도를 1920×1440 쪽으로 올렸다가 한 장 뜨고 되돌린다 ③ 그것도 안 되면 지금 영상 프레임 그대로. 긴 변이 2560px을 넘으면 줄이고 JPEG(품질 90%)로 보낸다.
  - 사진은 전용 통화 연결(DataChannel `photo`)로 조각내 보낸다. 서버에는 올리지도 저장하지도 않는다. 엔지니어 기기 메모리에만 있다가 **통화를 끝낼 때 저장할지 묻는다**([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).
  - 저장: 폰은 공유 창이 열린다(아이폰 '이미지 N개 저장' → 사진 앱, 안드로이드는 갤러리·드라이브 등을 고른다). PC나 공유 창이 없는 브라우저는 파일로 내려받는다. 파일 이름은 `bwadrim_2026-09-28_14-32-05_1.jpg`(한국 시간, 찍은 순서).
  - 화면 멈춤([CALL-09](#call-09--프리즈-프레임--드로잉-)) 중에는 버튼이 숨고, 연결이 잠깐 끊긴 동안에는 흐리다.
- **왜**: 원격으로 본 고장 부위(명판·에러 코드·배선)를 기록으로 남기거나 방문 준비에 쓰기 위해. 웹은 사진첩에 바로 쓸 수 없어 끝날 때 한 번에 공유 창으로 저장한다.
- **확인**: 연결 후 엔지니어가 카메라 버튼을 두 번 누른다. 고객 폰에 '기사님이 사진을 찍었어요'가 뜨고, 버튼 숫자가 2가 되는지 본다. 통화를 끝내면 결과 기록 맨 위에 사진 2장과 저장 버튼이 나오고, 저장하지 않고 '기록하고 끝내기'를 누르면 한 번 더 묻는지, '사진 저장하고 끝내기' → 아이폰 공유 창 '이미지 2개 저장' → 사진 앱에 들어가는지 본다. 고객 폰이 안드로이드일 때와 아이폰일 때 사진 해상도를 비교해 본다. 자동 테스트 `e2e/call-photo.spec.ts`(가짜 카메라로 두 장 찍기·고객 알림·저장 질문·다운로드 두 개·`photo_taken` 기록), 단위 테스트 `src/lib/webrtc/photo.test.ts`.
- **제약**:
  - **실기기로는 아직 확인하지 않았다.** 특히 아이폰에서 해상도를 잠깐 올릴 때 고객 화면이 잠깐 멈칫하거나, 폰에 따라 해상도가 안 올라 영상 화질 그대로일 수 있다. 안드로이드 사진 촬영 기능은 찍는 순간 초점을 다시 잡느라 1~2초 걸릴 수 있다.
  - 사진은 엔지니어 기기 메모리에만 있어서 **저장하지 않고 화면을 닫거나 새로고침하면 사라진다**. 통화 중에 다른 기기로 이어받아도([CALL-13](#call-13--다른-기기에서-이어받기-)) 사진은 옮겨 가지 않는다.
  - 받는 도중 연결이 끊기면 그 사진은 실패로 끝난다(다시 누르면 된다). 첫 조각이 12초 안에 안 오거나 조각 사이가 8초 넘게 끊겨도 실패.
  - 공유 창을 그냥 닫으면 저장되지 않는다(다시 누를 수 있다). PC에서 여러 장을 내려받을 때 브라우저가 '여러 파일 다운로드 허용'을 물을 수 있다.
  - 새 코드가 배포되기 전에 열어 둔 고객 화면은 `photo` 연결이 없어 사진을 받지 못한다(새로고침하면 된다).
  - 찍은 사진·장수는 서버에 남지 않는다(`photo_taken`은 처음 받았을 때 한 번만 기록).
- **관련 코드**: `src/lib/webrtc/photo.ts`(찍기·주고받기), `src/lib/webrtc/call.ts`(`photo` 채널), `src/lib/photo-save.ts`(저장), `src/app/(engineer)/room/[id]/call-panel.tsx`(버튼), `record-view.tsx`(저장 질문), `src/app/join/[token]/camera-start.tsx`(고객 쪽)

## 5. 연결 품질·TURN (NET)

### NET-01 · TURN 포함 연결 서버 ✅
- **동작**: 통화를 시작할 때마다(엔지니어 통화 대기 시작, 고객 '카메라 켜고 시작하기') 서버에서 연결 서버 목록을 받는다. Google STUN과 Cloudflare TURN이 들어 있다. Cloudflare 키는 서버에만 있고, 폰에는 2시간짜리 임시 자격증명만 내려간다. 브라우저가 막는 53번 포트 주소는 뺀다.

- **제약**: 자격증명은 버튼을 누를 때 한 번만 받는다. 2시간 넘게 대기하거나 통화하면 TURN이 안 될 수 있다.

### NET-03 · TURN 실패해도 통화는 계속 + 경고 ✅
- **동작**: TURN을 못 받으면(키 미설정, Cloudflare 오류 등) STUN만으로 연결을 시도한다. 엔지니어 대기 화면에 노란 경고 '중계 서버 없이 연결하고 있어요 / 모바일 데이터끼리는 연결이 안 될 수 있어요 (원인)'이 뜬다. 통화 화면에서는 위쪽 오른쪽에 노란 경고 아이콘만 있고, 누르면 같은 문구가 영상 위에 펼쳐진다(영상을 가리지 않게).
- **확인**: 경고의 괄호 안이 원인이다. `미설정`은 Vercel 환경 변수 누락, `cloudflare 401/403`은 토큰 오류, `cloudflare 404`는 Key ID 오류.
- **제약**: 고객 화면에는 경고가 없다. 세션 화면을 열어 둔 채 24시간이 지나면 '연결 준비' 때 '상담이 끝났거나 만료됐어요' 경고가 뜬다(새로 열면 만료 안내 화면이 나온다).

### DATA-02 · 핵심 지표 계산법 🚧
- **동작**: README의 지표 네 가지는 지금 데이터로 이렇게 뽑는다. 대시보드의 '통계' 화면([DATA-06](#data-06--통계-화면-))이 이 방식대로 계산해 보여 준다.

  | 지표 | 계산 | 주의 |
  |---|---|---|
  | 원격 해결률 | `resolved_remotely`가 true 또는 false인 세션 중 true 비율 (`rooms` 표) | 값이 비어 있는(null) 세션은 빼고 센다. 고객과 연결되지 않은 채 닫은 세션과, 엔지니어가 답하지 않은 세션이 null이다 |
  | 링크 → 카메라 허용 도달률 | `camera_granted`가 있는 세션 ÷ `link_opened`가 있는 세션 | 이벤트 개수가 아니라 **세션 단위**로 센다. `link_opened`에는 새로고침과 문자·카톡 미리보기 방문, 카톡에서 인터넷 앱으로 자동 전환한 두 번째 열기가 섞인다 |
  | 연결 실패율 / TURN 사용 비율 | 실패율 ≈ `camera_granted`는 있는데 `connected`가 없는 세션 비율. TURN 비율 = `connected`가 있는 세션 중 `relay_used`도 있는 세션 비율 | 실패 이벤트가 없어 실패율은 추정치다. 엔지니어가 '연결 준비'를 안 눌렀거나 고객이 기다리다 나간 세션도 실패로 잡혀 **실제보다 높게** 나온다. [NFR-05](#nfr-05--영상-연결은-브라우저-기본-기능으로-)의 5% 기준과 비교할 때는 이런 세션을 빼고 본다. TURN 경유는 고객 쪽 경로만 보고 판단한다. `connected`는 재연결마다 다시 쌓인다 |
  | 세션당 평균 시간 | `ended` 중 `resolved_remotely`가 null이 아닌 것의 `duration_sec` 평균 | **통화 시간이 아니라 세션을 만든 때부터** 잰다. 링크 보내고 기다린 시간이 들어간다. 고객과 연결되지 않은 채 닫은 세션(null)은 빼야 평균이 부풀지 않는다 |

### DATA-06 · 통계 화면 ✅

  - 그 아래 2×2 카드: 카메라 허용(링크 → 카메라 허용), 연결 실패율(추정), TURN 중계, 상담당 평균(시간) — 카드마다 숫자와 'N건 중 M건'. 계산은 [DATA-02](#data-02--핵심-지표-계산법-) 그대로
  - 도구 사용 카드: 연결된 세션 중 레이저 포인터·화면 멈춤을 쓴 세션 비율을 나란히
  - 카드마다 붙어 있던 주의점은 맨 아래 접힌 **'이렇게 셌어요'**에 모았다(원격 해결률은 답한 상담만, 연결 실패율은 실제보다 높게 나옴, TURN은 비용 근거, 평균은 상담을 만든 때부터)
  - 분모가 0이면 '—'. 세션이 없으면 '이 기간에 만든 상담이 없어요.' 화면 글자는 '세션' 대신 '상담'('상담당 평균' 등)

## 7. 공통 원칙 (NFR)

### NFR-01 · 고객은 탭 두 번 ✅
링크 → '카메라 켜고 시작하기' → '허용'. 로그인·설치·앱 없음.
- **제약**: 정상 흐름 기준이다. 카카오톡·라인 안에서 열면 인터넷 앱으로 자동 전환되고, 그 밖의 앱에서 열면 고객이 직접 인터넷 앱으로 열어야 한다 → [JOIN-10](#join-10--카카오톡-앱-안-브라우저-안내-). 연결이 실패하거나 잘못 끝내면 '다시 연결'을 한 번 눌러야 한다 → [JOIN-08](#join-08--고객이-종료-), [JOIN-09](#join-09--연결-실패-안내-). '통화 종료'는 확인 창에서 한 번 더 누른다.

### NFR-02 · 어르신 기준 화면 🚧
한국어, 큰 버튼, 한 화면에 한 가지 행동. 고객 화면은 본문 18px 이상, 제목 26~32px, 누를 버튼 64px 이상이고, 누를 것은 엄지가 닿는 화면 아래쪽에 둔다. 문구는 해요체로, 무엇을 누를지 버튼 이름 그대로 쓴다(''허용'을 눌러 주세요'). 설명은 짧게 — 큰 제목 하나와 한두 줄, 단계는 꼭 필요한 것만([NFR-08](#nfr-08--디자인-시스템-) 화면 짜임). 버튼 아이콘은 폰마다 모양이 다른 이모지 대신 같은 선 아이콘(`src/components/ui/icons.tsx`)을 쓴다. 실수로 화면이 확대되지 않게 모든 화면(엔지니어 화면 포함)의 배율을 고정했다. 글자 크기는 rem이라 폰의 글자 크기 설정을 따라 커진다.
- **제약**: 안드로이드에서는 작은 글씨를 손가락으로 확대할 수도 없다(아이폰은 확대됨). 필요하면 고정을 풀지 결정해야 한다. 폰이 다크 모드여도 모든 화면을 밝은 화면으로 고정해 보여 준다([BUG-10](#bug-10--다크-모드에서-글씨버튼-대비가-낮음-낮음) 해결). 다만 삼성 인터넷의 '웹페이지 다크 모드'처럼 브라우저가 강제로 색을 바꾸는 기능은 막지 못할 수 있다(실기기 확인 전). 통화 화면은 영상에 집중하도록 어두운 화면이다([NFR-08](#nfr-08--디자인-시스템-)). 한글은 어절 단위로 줄바꿈한다.

### NFR-03 · 카메라·마이크는 버튼을 누른 뒤에만 ✅
iOS 정책 때문에, 고객 '카메라 켜고 시작하기'와 엔지니어 '새 A/S 시작'·'이어하기'·'연결 준비'를 누른 뒤에만 권한을 묻는다. 엔지니어 마이크는 대시보드 탭 안에서 요청해 세션 화면으로 넘긴다([CALL-01](#call-01--엔지니어-연결-준비-)).

### NFR-04 · 폰에 세션 정보 저장 안 함 ✅
고객 폰은 공용일 수 있으므로 브라우저 저장소(localStorage)를 쓰지 않는다. 엔지니어 로그인은 쿠키만 쓴다.

### NFR-05 · 영상 연결은 브라우저 기본 기능으로 ✅
관리형 서비스(LiveKit 등) 없이 브라우저 내장 WebRTC로 폰끼리 직접 연결한다. 직접 연결이 안 될 때만 Cloudflare TURN이 중계한다. 연결 실패율이 5%를 넘는 상태가 이어지거나 재연결 안정화에 2주 이상 걸리면 LiveKit 전환을 다시 검토한다 (README 결정).

---

### NFR-06 · 통화 중 화면 꺼짐 방지 ✅
고객이 '카메라 켜고 시작하기', 엔지니어가 '새 A/S 시작'·'이어하기'·'연결 준비'를 누르면 통화가 끝날 때까지 폰 화면이 자동으로 꺼지지 않게 한다. 고객은 폰을 비추기만 하고 화면을 건드리지 않아 자동 잠금으로 끊기기 쉽기 때문이다. 앱이나 다른 탭에 갔다 돌아오면 다시 건다.
- **확인**: 폰의 자동 잠금을 30초로 해 두고 통화한다. 30초가 지나도 화면이 꺼지지 않는지 본다.
- **제약**: 브라우저가 지원하지 않거나 저전력 모드이면 안내 없이 적용되지 않는다(아이폰은 iOS 16.4 이상).

### NFR-07 · 고객 연락처는 저장하지 않음 ✅
고객(가맹점 사장님)의 이름·전화번호·연락처 목록을 저장하지 않는다. 받는 사람은 엔지니어 폰의 문자 앱·카카오톡이 최근 대화순·검색으로 골라 준다([ROOM-06](#room-06--문자로-보내기-), [ROOM-07](#room-07--다른-앱으로-공유-)).
- **왜**: A/S 때만 여는 앱이라 앱 안 주소록은 관리되지 않고, 문자·카톡의 최근 대화 목록보다 고르기 쉽지 않다. 저장하면 개인정보 처리 의무와 유출 책임이 생긴다. 앱으로 만들어도 연락처 전체 읽기는 막히는 추세다(iOS 18 부분 허용, 구글 플레이는 연락처 선택 창으로 충분하면 전체 권한 금지). 카카오 친구 목록 API는 친구도 우리 앱에 가입·동의해야 해서 쓸 수 없다. 전화 온 번호(통화 기록) 읽기도 아이폰은 불가, 안드로이드는 기본 전화 앱만 가능하다.
- **나중에**: 앱을 만들면 연락처 선택 창에서 한 명을 골라 바로 문자로 보내는 정도는 저장 없이 할 수 있다. 가맹점별 A/S 기록이 필요해지면 연락처가 아니라 세션에 가게 이름 한 줄을 붙이는 방식으로 검토한다.

### NFR-08 · 디자인 시스템 ✅
모든 화면은 피그마 디자인 시스템 v1(https://www.figma.com/design/Hqnz1fYrJJAhO7nDGNKRwn)과 같은 이름의 토큰(`src/app/globals.css`)과 부품으로 그린다 — 색, 글자(`text-display-l`·`text-title-*`·`text-body-*`·`text-label-*`), 그림자(`shadow-card`·`float`·`sheet`), 누르는 크기(48·56·64px), 선 아이콘(피그마 Icons, 2px 선), 로고(카메라 모양). 코드 부품은 `src/components/ui/`에 있고 피그마 컴포넌트와 이름이 같다: Button(primary·secondary·danger·ghost·kakao·call·call-danger·call-ghost × M·L·XL, 흐림·로딩, 아이콘 위·글자 아래 `stack` — 두세 개를 한 줄에 나란히 둘 때. 폰은 파란 문자 버튼 아래 보조 줄이고, 문자가 없는 PC는 이 줄이 곧 누를 것이라 파랑이 없다. 피그마에는 아직 없다), StatusChip, StepItem, Banner(밝은 화면 안에서는 그림자 없는 `flat`), CallControl, StatCard, EngineerCard, Sheet, NoticeScreen, BottomCta(화면 아래에 붙는 버튼 자리), Brand·BrandMark, Icons(공유하기 `ShareIcon`·사진 저장 `DownloadIcon`은 피그마에 아직 없다). 방향 지시 알약은 `src/components/guide-pill.tsx`.
- **화면 짜임(토스식)**: 한 화면에 큰 제목(26~32px) 하나 — 그 화면에서 할 일이나 지금 상태를 말한다('고객님께 링크를 보내 주세요', '출장 없이 해결됐나요?'). 설명은 그 아래 회색 한 줄. 누를 것은 화면 아래(`BottomCta`, 스크롤해도 붙어 있고 위 가장자리는 흐려짐). 위쪽 바에는 제목을 쓰지 않는다(뒤로가기·닫기만)
- 묶음은 테두리 상자 대신 면으로: 흰 화면 안에서는 회색 카드(`bg-bg-subtle`, 모서리 24), 목록 화면(대시보드·통계)은 회색 바탕(`bg-bg-muted`)에 흰 카드. 그림자는 영상 위에 겹치는 것과 확인 창에만
- 파랑(`primary`)은 한 화면에 "지금 누를 것" 하나. 보조 동작은 옅은 회색 바탕(`secondary`, 테두리 없음)이나 글자 버튼(`ghost`), 선택 상태는 흰 바탕 + 진한 테두리나 진한 회색 등 중립색
- 빨강(`danger`)은 종료·오류·'방문 필요'에만. 종료는 확인 단계를 한 번 거친다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-), [JOIN-08](#join-08--고객이-종료-))
- 노랑은 방향 지시(`guide-signal`)와 경고 띠에만. 예외: 카톡 보내기 버튼(카카오 색), 고객 '허용' 화살표([JOIN-02](#join-02--시작-화면-), 방향 안내와 같은 뜻)
- 통화 화면은 어두운 표면(`call-*`), 그 밖은 밝은 화면. 켜진 도구(손전등)는 흰 동그라미(`active`)
- 해결 여부처럼 지표가 되는 답은 같은 모양으로 보여 준다(한쪽을 강조하지 않는다)
- **제약**: 가리키기(레이저 포인터·AR 핀·그림)는 디자인 시스템(`pointer` = 브랜드 블루)과 달리 빨강이다([CALL-08](#call-08--레이저-포인터-)). 고객 이름·전화번호 입력, 방 코드는 없고([NFR-07](#nfr-07--고객-연락처는-저장하지-않음-), [ROOM-02](#room-02--접속-코드--폐기-2026-09-24) 폐기) 상담은 시각으로 구분하며, 고객에게는 '엔지니어' 대신 '기사님'이라고 부른다. 피그마 화면(E03·E04·E11, 고객 화면 문구)과 부품(아이콘 18개, Button Kakao·Call 계열·Loading, StepItem Error)도 2026-09-28에 이대로 맞췄고, Components 페이지의 '결정 메모'에 적어 두었다. **같은 날 뒤이은 토스식 개편(화면 짜임, secondary 회색 바탕, StatCard·EngineerCard 모양, BottomCta, 화면별 배치)은 아직 피그마에 반영하지 않았다** — 지금은 코드가 기준이다.
- **관련 코드**: `src/app/globals.css`, `src/components/ui/`, `src/app/icon.svg`·`apple-icon.png`

## 8. 운영 설정 (OPS)

### OPS-01 · 환경 변수 ✅
Vercel → Settings → Environment Variables에 5개를 넣고 **Redeploy**한다. 값을 바꿔도 다시 배포해야 반영된다.

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase publishable 키 (`sb_publishable_…`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase secret 키 (`sb_secret_…`). 서버 전용 |
| `CLOUDFLARE_TURN_KEY_ID` | Cloudflare → Realtime → TURN의 Key ID |
| `CLOUDFLARE_TURN_API_TOKEN` | 같은 곳의 API Token |

- **제약**: 변수마다 적용 환경(Production·Preview·Development)을 고른다. **Preview에 체크하지 않으면 main이 아닌 브랜치의 미리보기 주소는 모든 화면이 'Internal Server Error'가 된다**(로그인 확인이 Supabase 주소를 못 찾음). 예외는 로그인이 필요 없는 실험실 `/lab/*`. 미리보기에서도 통화까지 시험하려면 Preview에도 체크하고 Redeploy한다(운영과 같은 DB·TURN을 쓰게 된다는 점에 주의).

### OPS-02 · Vercel 배포 보호 끄기 ✅
Vercel → Settings → Deployment Protection → **Vercel Authentication 끄기**. 켜져 있으면 고객 폰에 Vercel 로그인 화면이 뜬다.

### OPS-03 · 엔지니어 계정 만들기 ✅
Supabase → Authentication → Users → Add user → Create new user. **Auto Confirm User를 체크**해야 바로 로그인된다.
- **표시 이름**: 만든 사용자의 **User Metadata**에 `{"name": "김도현"}`을 넣으면 고객 시작 화면의 '기다리고 있는 기사님' 카드([JOIN-02](#join-02--시작-화면-)), 고객 통화 화면 위쪽([JOIN-06](#join-06--고객-통화-화면-)), 대시보드 인사([ROOM-04](#room-04--최근-세션-목록-))에 이름이 나온다(20자까지). 없으면 이름 없이 '기사님'으로 보인다. `full_name`·`display_name`도 읽는다.
- **제약**: 고객 링크를 연 사람은 누구나 그 세션 엔지니어의 표시 이름을 볼 수 있다. 실명 대신 '김 기사' 같은 이름을 써도 된다.
- **관련 코드**: `src/lib/engineer-name.ts`

### OPS-04 · DB 준비 ✅
Supabase → SQL Editor에서 `supabase/schema.sql` 전체를 실행한다. 여러 번 실행해도 된다.
- **제약**: 이미 있는 표는 건너뛰므로, 나중에 칸을 바꾸면 이 파일을 다시 실행하는 것만으로는 기존 DB에 반영되지 않는다. 규칙(정책)·함수는 다시 실행하면 새로 반영된다.

### OPS-05 · Realtime 공개 채널 끄기 ✅
Supabase → Realtime → Settings → **Allow public access(공개 채널 허용) 끄기**. 켜 두면 비공개 설정을 뺀 채널이 [CALL-12](#call-12--엔지니어-사칭-차단-)의 규칙을 거치지 않을 수 있다.
- **순서**: ① [OPS-04](#ops-04--db-준비-)로 규칙을 넣고 ② 새 코드를 배포하고 ③ 통화가 되는지 확인한 **뒤에** 끈다.
- **적용**: 2026-09-24 운영 프로젝트에서 끔.

## 알려진 문제

코드로 확인된 버그와 빈틈이다. 우선순위는 **높음**(핵심 흐름이나 핵심 지표가 깨짐) · **중간** · **낮음**. 해결된 항목도 번호를 남겨 두고 **상태** 줄에 해결 날짜를 적는다.

### BUG-01 · 고객이 먼저 종료하면 엔지니어 화면이 멈춤 (높음)
**상태**: ✅ 해결 (2026-09-24). 고객이 종료하면 엔지니어 화면에 '고객님이 통화를 종료했어요'와 해결 여부 질문이 뜬다.

고객이 '종료'를 누르면 엔지니어 화면이 종료 버튼 없는 '고객님 접속됨 — 연결 중…'에 멈춘다. 그래서 '출장 없이 해결됐나요?'를 입력할 수 없고, 세션은 '연결됨'으로 남으며, 핵심 지표(원격 해결률)가 빠진다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-), [JOIN-08](#join-08--고객이-종료-)

### BUG-02 · 고객이 안 들어온 세션을 끝낼 수 없음 (높음)
**상태**: ✅ 해결 (2026-09-24). 모든 단계에 끝내는 버튼을 두고, 연결된 적 없는 세션은 '상담 닫기'(당시 '세션 닫기')로 해결 여부 없이 닫는다.

'연결 준비' 전 화면과 대기 화면에 종료 버튼이 없다. 고객이 끝내 안 들어온 세션은 대시보드에 '대기 중'으로 계속 쌓인다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-), [CALL-04](#call-04--엔지니어-통화-화면-)

### BUG-03 · 연결 전에 카메라를 바꾸면 엔지니어에게 검은 화면 (높음)
**상태**: ✅ 해결 (2026-09-24). 카메라를 바꾸면 이후에 맺는 연결에도 바꾼 카메라가 간다.

고객이 '기사님을 기다리는 중…'일 때 🔄를 누르면, 연결됐을 때 엔지니어 화면에 영상이 안 나온다. 통화 중에 바꾼 뒤 재연결될 때도 같다. 관련: [JOIN-07](#join-07--카메라-전후면-전환-), [CALL-05](#call-05--나갔다-들어오면-재연결-)

### BUG-04 · 같은 역할이 두 기기에서 들어오면 연결이 꼬임 (중간)
**상태**: ✅ 해결 (2026-09-24). 늦게 들어온 기기가 이어받는다([CALL-13](#call-13--다른-기기에서-이어받기-)). 모의 테스트로 확인, 실기기 확인 전.

엔지니어가 같은 세션을 폰과 PC에서 둘 다 '연결 준비'하거나 버튼을 두 번 누르면, 또는 고객 링크를 두 기기에서 열면 서로의 연결을 끊는다. 링크가 새면 진행 중인 상담에 다른 사람이 끼어들 수 있다. 관련: [ROOM-03](#room-03--초대-링크-유효기간-), [CALL-01](#call-01--엔지니어-연결-준비-)

### BUG-05 · 종료·실패 뒤에 화면이 되살아남 (중간)
**상태**: ✅ 해결 (2026-09-24). 고객은 종료·실패하면 채널에서 나가고, 엔지니어는 직접 종료하면 채널에서 나간다. 고객이 먼저 종료한 경우에만 엔지니어가 남아 있다가, 고객이 링크를 다시 열면 이어받는다(의도한 동작).

종료하거나 실패한 뒤에도 신호 채널이 연결된 채로 남는다. 그래서 상대가 다시 들어오면 '상담이 끝났습니다'나 '출장 없이 해결됐나요?' 화면이 통화 화면으로 돌아간다. 고객 쪽이 되살아나면 이미 꺼진 카메라로 연결돼 엔지니어에게 검은 화면이 간다. 엔지니어 쪽이 되살아나면(고객이 링크를 다시 연 경우) 영상은 정상이지만 '출장 없이 해결됐나요?' 질문이 사라져 '종료'를 다시 눌러야 한다. 관련: [CALL-05](#call-05--나갔다-들어오면-재연결-)

### BUG-06 · 대시보드 시각이 한국 시간이 아닐 수 있음 (중간)
**상태**: ✅ 해결 (2026-09-24). 시각을 한국 시간(Asia/Seoul)으로 고정했다.

세션 시각을 서버에서 시간대 지정 없이 만든다. Vercel 서버는 UTC라서 9시간 이르게 보일 가능성이 높다. 관련: [ROOM-04](#room-04--최근-세션-목록-)

### BUG-07 · 만료된 세션이 엔지니어 화면에서 살아 있는 것처럼 보임 (중간)
**상태**: ✅ 해결 (2026-09-24). 대시보드는 '만료'로, 세션 화면은 만료 안내로 보여 주고 공유 버튼·통화를 숨긴다. DB 상태는 바꾸지 않는다.

24시간이 지난 세션도 대시보드에 '대기 중'으로, 세션 화면에 공유 버튼과 함께 보인다. 쓸 수 없는 링크를 보내게 된다. '연결 준비'를 누르면 그제야 '세션이 종료됐거나 만료됐어요' 경고가 뜬다. 관련: [ROOM-03](#room-03--초대-링크-유효기간-), [NET-03](#net-03--turn-실패해도-통화는-계속--경고-)

### BUG-08 · 로그인 후 이동 주소 검사에 빈틈 (중간·보안)
**상태**: ✅ 해결 (2026-09-24). 이동할 주소를 실제로 해석해 같은 사이트 안의 경로가 아니면 대시보드로 보낸다. `/\다른사이트`, `//다른사이트`, `/..//다른사이트`, 공백 포함 주소를 검사로 확인.

`/login?next=/\다른사이트` 같은 링크로 로그인하면 로그인 직후 외부 사이트로 넘어갈 수 있다. 가짜 로그인 링크로 엔지니어를 속이는 데 쓰일 수 있다. 관련: [AUTH-04](#auth-04--엔지니어-화면-보호-)

### BUG-09 · 통화 신호 채널에 접근 제한이 없음 (중간·보안)
**상태**: ✅ 해결 (2026-09-24). 엔지니어 사칭과 종료·만료된 세션 입장은 막았다([CALL-12](#call-12--엔지니어-사칭-차단-), 2026-09-24 운영 적용). 링크를 가진 사람은 고객으로 들어올 수 있지만 엔지니어에게 알림이 뜬다([CALL-13](#call-13--다른-기기에서-이어받기-)).

(해결 전 내용) 신호 채널(`room:{세션 ID}`)이 공개 채널이다. 세션 ID는 고객 페이지에 담겨 내려가므로, 링크를 연 적 있는 사람은 진행 중인 통화에 끼어들거나 끊는 신호를 보낼 수 있다. 링크가 만료돼 고객 페이지가 더 이상 안 열려도 마찬가지다. 종료 처리된 세션은 통화 자체가 열리지 않으므로 해당 없다. 관련: [DATA-05](#data-05--데이터-접근-권한-)

### BUG-10 · 다크 모드에서 글씨·버튼 대비가 낮음 (낮음)
**상태**: ✅ 해결 (2026-09-24). 모든 화면을 밝은 화면으로 고정했다(다크 모드 흉내 브라우저로 흰 배경 확인). 브라우저가 강제로 색을 바꾸는 기능은 실기기 확인 전.

폰이 다크 모드면 배경이 거의 검게 바뀌는데, 검은 버튼과 회색 글씨는 그대로라 잘 안 보인다. 관련: [JOIN-02](#join-02--시작-화면-)

### BUG-11 · 새 세션 버튼 중복 클릭 (낮음)

'+ 새 원격 A/S 시작'이 처리 중에 잠기지 않아 여러 번 누르면 세션이 여러 개 생긴다. 관련: [ROOM-01](#room-01--새-세션-만들기-)

### BUG-12 · 종료 저장 실패 안내 없음 (낮음)
**상태**: ✅ 해결 (2026-09-24). 실패하면 '저장에 실패했어요. 다시 눌러주세요.'가 나온다.

'출장 없이 해결됐나요?' 저장이 실패해도 안내 없이 버튼만 다시 눌린다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)

### BUG-13 · 404·오류 화면이 영어 기본 화면 (낮음)
**상태**: ✅ 해결 (2026-09-24). 없는 주소는 '페이지를 찾을 수 없어요', 서버 오류는 '잠깐 문제가 생겼어요 / 다시 시도'.

없는 세션 주소나 세션 만들기 실패 때 Next.js 기본 영어 화면이 나온다. 관련: [AUTH-08](#auth-08--자기-세션만-보기-), [ROOM-01](#room-01--새-세션-만들기-)

### BUG-14 · 지표 정확도 (낮음)
`link_opened`에 새로고침·미리보기 방문이 섞이고, `connected`·`relay_used`가 재연결마다 쌓이고, TURN 경유를 고객 쪽만 보고 판단하고, `ended` 시간은 세션 생성부터 잰다. 연결 실패 이벤트는 없다. 당장은 [DATA-02](#data-02--핵심-지표-계산법-)의 주의사항대로 세션 단위로 세면 된다.

### BUG-15 · 고객용 서버 기능에 횟수 제한·검사 없음 (낮음·보안)
TURN 발급과 고객 지표 기록은 유효한 링크 토큰만 있으면 몇 번이든 부를 수 있고, 기록의 부가정보도 검사하지 않는다. 가짜 지표가 쌓이거나 TURN 사용량이 늘 수 있다. 관련: [NET-02](#net-02--유효한-코드에만-발급-), [DATA-04](#data-04--고객-쪽-기록-제한-)

### BUG-17 · '연결 준비'를 잊으면 고객이 계속 기다림 (중간)

### BUG-18 · 답하기 전에 다른 기기가 이어받아도 질문이 남음 (낮음)
