# 봐드림 기능 요구사항

제품이 **지금 실제로 어떻게 동작하는지** 적은 기준 문서다. 기능을 바꿀 때는 이 문서의 요구사항 ID(예: `CALL-03`)로 이야기하고, 코드를 바꾸는 커밋에서 이 문서도 같이 고친다.

- 기준일: 2026-09-24
- 상태 표기: ✅ 구현됨 · 🚧 일부만 구현됨 (제약 참고) · ⬜ 예정
- 각 요구사항은 **동작**(무엇을 하나), **확인**(폰으로 어떻게 확인하나), **제약**(안 되는 것·주의할 점)으로 적는다
- 알려진 버그는 맨 아래 [알려진 문제](#알려진-문제)에 `BUG-번호`로 모아 두고, 관련 요구사항에서 가리킨다

## 용어

| 용어 | 뜻 |
|---|---|
| 엔지니어 | 로그인해서 원격 A/S를 하는 사람 (폰 또는 PC 웹) |
| 고객 | 문자로 받은 링크를 열어 폰 카메라로 비춰 주는 사람. 로그인 없음 |
| 세션 | 원격 A/S 한 건. 코드와 DB에서는 `room`(방)이라고 부른다 |
| 접속 코드 | 세션마다 붙는 6자리 코드. 고객 링크 끝에 붙는다 (`/join/코드`) |
| 세션 상태 | **대기 중**(아직 연결된 적 없음) → **연결됨**(한 번이라도 연결된 적 있음) → **종료**(엔지니어가 종료 처리함). 연결에 실패한 채 종료하면 '대기 중'에서 바로 '종료'가 된다 |
| TURN | 폰끼리 직접 연결이 안 될 때(5G끼리 등) 영상을 중간에서 전달해 주는 서버. Cloudflare를 쓴다 |

## 1. 엔지니어 로그인·접근 (AUTH)

### AUTH-01 · 첫 화면 ✅
- **동작**: 사이트 주소를 열면 '봐드림' 이름, 한 줄 소개, '엔지니어 로그인' 버튼, 고객 안내 문구('고객님은 문자로 받으신 링크를 눌러주세요.')가 보인다. 이미 로그인했으면 버튼을 눌렀을 때 바로 대시보드로 간다.
- **확인**: 배포 주소 첫 화면을 연다. 로그아웃 상태면 버튼이 로그인 화면으로, 로그인 상태면 대시보드로 간다.

### AUTH-02 · 이메일·비밀번호 로그인 ✅
- **동작**: 이메일·비밀번호 입력칸과 '로그인' 버튼이 폰에서 누르기 쉽게 크다. 이메일 칸에는 이메일 키보드가 뜨고, 저장된 비밀번호 자동 채우기가 된다. 처리 중에는 버튼이 '로그인 중…'으로 바뀌고 눌리지 않는다. 성공하면 대시보드로 간다.
- **확인**: `/login`에서 로그인해 대시보드가 나오는지 본다.
- **제약**: 회원가입·비밀번호 찾기·비밀번호 변경 화면이 없다. 계정은 [OPS-03](#ops-03--엔지니어-계정-만들기-)대로 Supabase에서 직접 만든다.

### AUTH-03 · 로그인 실패 안내 ✅
- **동작**: 이메일이나 비밀번호가 틀리면 로그인 화면에 머물고 빨간 글씨로 '이메일 또는 비밀번호가 올바르지 않습니다.'가 나온다. 어느 쪽이 틀렸는지는 알려 주지 않는다.
- **확인**: 틀린 비밀번호로 로그인해 본다.
- **제약**: 서버 장애나 시도 횟수 제한도 같은 문구로 나온다. 실패 후 입력칸이 비워질 수 있다.

### AUTH-04 · 엔지니어 화면 보호 🚧
- **동작**: 로그인하지 않고 대시보드나 세션 화면을 열면 로그인 화면으로 보낸다. 로그인하면 원래 열려던 화면으로 돌아간다. 이미 로그인한 상태로 로그인 화면을 열면 대시보드로 보낸다.
- **확인**: 시크릿 창에서 `/dashboard`를 연다. 로그인 화면으로 바뀌고, 로그인하면 대시보드로 간다.
- **제약**: 돌아갈 주소를 검사하는 부분에 빈틈이 있다 → [BUG-08](#bug-08--로그인-후-이동-주소-검사에-빈틈-중간보안)

### AUTH-05 · 로그인 유지 ✅
- **동작**: 브라우저를 닫았다 열어도 로그인이 유지되고, 만료가 가까워지면 자동으로 갱신된다. 로그인 정보는 쿠키에만 둔다.
- **확인**: 로그인 후 브라우저를 완전히 닫았다 다시 열고 `/dashboard`가 바로 열리는지 본다.

### AUTH-06 · 로그아웃 ✅
- **동작**: 대시보드 오른쪽 위 '로그아웃'을 누르면 로그인 화면으로 간다.
- **제약**: 같은 계정으로 로그인한 **모든 기기**가 함께 로그아웃된다 (PC에서 로그아웃하면 폰도 풀림). 세션 화면에는 로그아웃 버튼이 없다.

### AUTH-07 · 고객 쪽은 로그인 없이 공개 ✅
- **동작**: 고객 링크(`/join/코드`)와 고객이 쓰는 서버 기능(TURN 발급, 지표 기록)은 로그인 없이 쓸 수 있다. 로그인 보호는 대시보드와 세션 화면에만 있다.
- **확인**: 로그인한 적 없는 폰에서 고객 링크를 열면 바로 '카메라 켜기' 화면이 나온다.

### AUTH-08 · 자기 세션만 보기 ✅
- **동작**: 엔지니어는 자기가 만든 세션만 목록에서 보고, 열고, 종료할 수 있다. 다른 엔지니어의 세션 주소를 열면 404 화면이 나온다.
- **확인**: 엔지니어 계정 두 개로 서로의 세션이 안 보이는지 확인한다.
- **제약**: 이 보호는 Supabase 보안 정책(RLS)에 달려 있어서 `schema.sql`을 실행해 둬야 한다. 404 화면은 영어 기본 화면이다 → [BUG-13](#bug-13--404오류-화면이-영어-기본-화면-낮음)

## 2. 세션 만들기·공유·종료 (ROOM)

### ROOM-01 · 새 세션 만들기 ✅
- **동작**: 대시보드의 '+ 새 원격 A/S 시작'을 한 번 누르면 세션이 만들어지고 바로 세션 화면으로 간다.
- **확인**: 버튼을 눌러 접속 코드가 크게 보이는 화면으로 넘어가는지 본다.
- **제약**: 누르는 동안 버튼이 잠기지 않아 여러 번 누르면 세션이 여러 개 생긴다 → [BUG-11](#bug-11--새-세션-버튼-중복-클릭-낮음). 실패하면 영어 오류 화면이 뜬다.

### ROOM-02 · 접속 코드 ✅
- **동작**: 세션마다 6자리 코드가 붙는다. 영문 대문자와 숫자 2~9만 쓰고 헷갈리는 0·1·O·I·L은 뺀다. 겹치면 새로 뽑는다. 링크 끝 코드가 소문자로 바뀌어 있어도 같은 세션으로 들어간다.
- **확인**: 세션 몇 개를 만들어 코드에 0·1·O·I·L이 없는지 본다.
- **제약**: 고객이 코드를 직접 입력하는 화면은 없다. 코드는 링크의 일부로만 쓰이고, 화면에 크게 보이는 것은 엔지니어가 눈으로 확인하는 용도다.

### ROOM-03 · 초대 링크 유효기간 🚧
- **동작**: 링크는 세션을 만들고 24시간이 지나거나, 엔지니어가 종료 처리하면 더 이상 쓸 수 없다. 고객이 열면 '종료된 연결이에요' 안내가 나온다.
- **확인**: 세션을 종료한 뒤 같은 링크를 열어 본다.
- **제약**:
  - **1회용이 아니다.** 유효기간 안에는 같은 링크를 몇 번이든, 여러 기기에서 열 수 있다 → [BUG-04](#bug-04--같은-역할이-두-기기에서-들어오면-연결이-꼬임-중간)
  - 24시간이 지나면 대시보드에는 '만료'로, 세션 화면에는 만료 안내로 보인다([ROOM-04](#room-04--최근-세션-목록-), [ROOM-11](#room-11--종료된-세션-화면-)). 다만 DB 상태가 저절로 '종료'가 되지는 않아서 원격 해결 여부는 비어 있다(원격 해결률 계산에서 빠짐).

### ROOM-04 · 최근 세션 목록 ✅
- **동작**: 대시보드에 내 세션이 최신순으로 최대 20개 보인다. 각 줄에 접속 코드, 만든 날짜·시각, 상태(노랑 '대기 중' / 초록 '연결됨' / 회색 '종료'), 원격 해결한 세션에는 '· 원격 해결'이 붙는다. 줄을 누르면 그 세션 화면으로 간다.
- **확인**: 세션 몇 개를 만들고 끝낸 뒤 목록의 상태 색과 표시를 본다.
- **제약**: 20개를 넘으면 오래된 것은 안 보인다. 화면을 새로고침해야 상태가 바뀐다. 고객 이름이 없어 코드와 시각으로만 구분한다. 시각은 한국 시간으로 표시한다. 종료 처리 없이 24시간이 지난 세션은 회색 '만료'로 보인다.

### ROOM-05 · 세션 화면 ✅
- **동작**: 큰 접속 코드, 고객에게 보낼 링크 주소, 공유 버튼 최대 세 개([ROOM-06](#room-06--문자로-보내기-)~[08](#room-08--링크-복사-). '카톡 등으로 공유'는 공유 기능이 있는 브라우저에서만 보여서 PC에서는 두 개일 수 있다), 통화 영역([CALL](#4-영상음성-통화-call)), 대시보드로 돌아가는 ←가 있다.
- **제약**: 링크 주소는 엔지니어가 지금 접속한 주소를 기준으로 만든다. 미리보기 주소로 들어왔으면 그 주소가 고객에게 간다. 통화 중에도 코드와 공유 버튼이 그대로 있어 폰에서는 영상 영역이 작다.

### ROOM-06 · 문자로 보내기 ✅
- **동작**: 엔지니어 폰의 문자 앱을 열고 본문에 '[봐드림] 아래 링크를 눌러 폰 카메라로 비춰주세요.'와 링크를 미리 채운다. 엔지니어 본인 번호로 가므로 문자 API나 발신번호 등록이 필요 없다. 아이폰과 안드로이드의 문자 앱 여는 방식 차이를 처리한다.
- **확인**: 아이폰·안드로이드에서 버튼을 눌러 본문이 채워지는지 본다.
- **제약**: 받는 번호는 엔지니어가 직접 입력한다. PC에서는 동작하지 않을 수 있다.

### ROOM-07 · 카톡 등으로 공유 ✅
- **동작**: 공유 기능이 있는 브라우저에서만 버튼이 보이고, 누르면 기기 공유 창이 문자와 같은 문구로 열린다. 공유 창을 그냥 닫아도 오류가 나지 않는다.
- **제약**: 카카오톡으로 받은 고객은 카톡 안에서 링크를 열게 되는데, 자동으로 인터넷 앱으로 다시 열어 준다 → [JOIN-10](#join-10--카카오톡-앱-안-브라우저-안내-)

### ROOM-08 · 링크 복사 ✅
- **동작**: 링크 주소만 복사하고 버튼이 2초 동안 '복사됐어요 ✓'로 바뀐다.
- **제약**: 복사에 실패하면 안내가 없다. 화면의 주소를 직접 복사해야 한다.

### ROOM-09 · 세션 상태 바뀌는 시점 ✅
- **동작**: 만들 때 '대기 중' → 엔지니어 화면에서 처음 영상이 연결되면 '연결됨' → 엔지니어가 [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)으로 종료하면 '종료'. 한 번도 연결되지 않은 세션을 '세션 닫기'로 닫으면 '대기 중'에서 바로 '종료'가 되고 원격 해결 여부는 비워 둔다.
- **제약**: '연결됨'은 "지금 통화 중"이 아니라 "한 번이라도 연결됐었다"는 뜻이다. 끊겨도 '대기 중'으로 돌아가지 않는다. 엔지니어가 세션 화면을 열어 둔 상태에서 연결돼야 바뀐다.

### ROOM-10 · 종료와 '출장 없이 해결?' 입력 ✅
- **동작**: 세션 화면 어느 단계에서든 끝낼 수 있다. 버튼은 세션이 **한 번이라도 연결됐는지**에 따라 다르다.
  - **연결된 적 있음**: '종료'(영상 화면) 또는 '통화 종료'(그 밖의 화면)를 누르면 고객 화면이 '상담이 끝났습니다'로 바뀌고, 엔지니어 화면에 '출장 없이 해결됐나요?'가 뜬다. '네, 원격으로 해결' / '아니요, 출장 필요'를 고르면 세션이 '종료'로 저장되고(종료 시각, 원격 해결 여부 포함) 대시보드로 간다.
  - **연결된 적 없음**(고객이 안 들어왔거나 연결에 실패): '세션 닫기'를 누르면 '세션을 닫을까요? 고객님께 보낸 링크도 더 이상 열리지 않아요.' 확인이 나온다. '네, 닫기'를 누르면 해결 여부를 묻지 않고 종료한다(원격 해결률 계산에서 빠짐). 기다리던 고객 화면은 '상담이 끝났습니다'로 바뀐다. '취소'를 누르면 돌아간다. '연결 준비'를 처리하는 동안에는 이 버튼이 잠긴다.
  - **고객이 먼저 종료**: 엔지니어 화면에 '고객님이 통화를 종료했어요'와 위 질문(연결된 적 없으면 '세션 닫기')이 뜬다. 답하기 전에 고객이 링크를 다시 열면 통화로 돌아간다.
  - 확인 화면이 뜬 직후(0.6초)의 탭은 무시한다. 종료 버튼을 두 번 눌러 두 번째 탭이 답 버튼에 떨어지는 것을 막기 위해서다.
  - 로그인이 풀린 상태에서 답하면 로그인 화면으로 가고, 다시 로그인하면 이 세션 화면으로 돌아온다(답은 다시 해야 한다). 인증 서버가 잠깐 응답하지 않은 경우는 로그인 화면 대신 '저장에 실패했어요'로 다시 누르게 한다.
  - 저장하는 동안 버튼은 잠기고, 저장에 실패하면 '저장에 실패했어요. 다시 눌러주세요.'가 나온다. 고객에게 이미 종료를 알린 뒤라 되돌릴 수는 없고 다시 누르기만 할 수 있다. 고객이 먼저 끊은 경우에는 저장에 실패해도 계속 기다리므로, 고객이 링크를 다시 열면 이어진다.
- **확인**: (1) 연결 후 '종료' → 두 답 중 하나. (2) 고객 없이 '연결 준비' → '세션 닫기' → '네, 닫기'. (3) 연결 후 고객 폰에서 '종료'. 세 경우 모두 대시보드에서 '종료'로 보이고, (1)에서 '네'를 골랐을 때만 '· 원격 해결'이 붙는지 본다.
- **제약**: 질문에 답하기 전에 화면을 닫으면 세션은 종료되지 않고 링크도 살아 있다. 엔지니어가 '종료'를 누른 뒤에는 고객이 링크를 다시 열어도 통화로 돌아가지 않는다('기사님을 기다리는 중…'에 머묾).

### ROOM-11 · 종료된 세션 화면 ✅
- **동작**: 종료된 세션을 다시 열면 '종료된 세션입니다. 새 세션은 대시보드에서 시작하세요.'와 ←만 보인다. 종료 처리 없이 24시간이 지난 세션은 '만료된 세션입니다. 만든 지 24시간이 지나 고객 링크가 더 이상 열리지 않아요.'가 보인다. 둘 다 공유 버튼과 통화 기능은 없다.

## 3. 고객 진입 (JOIN)

### JOIN-01 · 링크만으로 진입 ✅
- **동작**: 고객은 로그인·설치 없이 링크를 누르면 바로 시작 화면을 본다.
- **확인**: 처음 쓰는 폰에서 링크를 열어 로그인 없이 '카메라 켜기'가 나오는지 본다.

### JOIN-02 · 시작 화면 ✅
- **동작**: 한 가지 행동만 보여 준다. '봐드림', '아래 버튼을 누르고 "허용"을 눌러주세요.', 큰 '📷 카메라 켜기' 버튼, '기사님이 화면을 보고 도와드립니다.'
- **제약**: 폰이 다크 모드면 글씨와 버튼이 잘 안 보일 수 있다 → [BUG-10](#bug-10--다크-모드에서-글씨버튼-대비가-낮음-낮음)

### JOIN-03 · 잘못된 링크 안내 ✅
- **동작**: 상황마다 큰 글씨 안내가 나온다.
  - 없는 코드: '주소를 확인해 주세요 / 문자로 받으신 링크를 다시 한 번 눌러주세요.'
  - 종료·만료된 세션: '종료된 연결이에요 / 기사님께 새 링크를 보내달라고 말씀해 주세요.' 링크를 열어 둔 사이에 세션이 닫혔다면 '카메라 켜기'를 누를 때(또는 통화 채널이 입장을 거부할 때, [CALL-12](#call-12--엔지니어-사칭-차단-)) 같은 안내가 나오고 카메라는 꺼진다.
  - 서버 오류: '잠시 연결이 원활하지 않아요 / 화면을 아래로 당겨 새로고침하거나, 잠시 후 다시 눌러주세요.'
- **확인**: 링크 끝 코드를 아무 글자로 바꿔 열어 본다.

### JOIN-04 · 카메라 켜기 ✅
- **동작**: '카메라 켜기'를 누른 **뒤에만** 카메라·마이크 권한을 묻는다. 뒷면 카메라를 먼저 쓴다. 처리 중에는 버튼이 '카메라 켜는 중…'으로 바뀌고 잠긴다. 허용하면 더 누를 것 없이 통화 화면으로 간다.
- **확인**: 링크를 열 때는 권한 창이 안 뜨고, 버튼을 눌러야 뜨는지 본다.
- **제약**: 카메라와 마이크를 한 번에 묻는다. 마이크만 거부해도 진행할 수 없다.

### JOIN-05 · 카메라 거부 안내 ✅
- **동작**: 거부하거나 카메라를 쓸 수 없으면 '카메라를 켤 수 없어요'와 '화면에 "허용" 창이 뜨면 눌러주세요. 창이 안 뜨면 화면을 새로고침한 뒤 다시 시도해 주세요.' 안내, 큰 '다시 시도' 버튼이 나온다.
- **확인**: 권한 창에서 '허용 안 함'을 눌러 본다.
- **제약**: 원인(거부, 카메라 없음, 다른 앱이 사용 중, 카톡 브라우저)을 구분하지 않는다. 한 번 '허용 안 함'을 누르면 브라우저가 기억할 수 있어서(특히 안드로이드 크롬), '다시 시도'나 새로고침을 해도 권한 창이 다시 안 뜬다. 이때는 폰 설정에서 권한을 켜야 하는데, 그 방법은 안내하지 않는다.

### JOIN-06 · 고객 통화 화면 ✅
- **동작**: 내 카메라 화면이 **잘리지 않고 전체**로 나온다(화면 비율이 다르면 위아래나 좌우에 검은 여백이 생긴다). 기사님이 가리키면 빨간 동그라미가 뜨고([CALL-08](#call-08--레이저-포인터-)), 기사님이 화면을 멈추면 같은 정지 화면과 그림이 보인다([CALL-09](#call-09--프리즈-프레임--드로잉-)). 위쪽 상태 표시가 '기사님을 기다리는 중…' → '기사님과 연결 중…' → 초록색 '기사님이 보고 있어요'로 바뀐다. 기사님 목소리가 들린다(기사님 영상은 없음). 아래에 카메라 전환(🔄)과 빨간 '종료' 버튼이 있다.
- **확인**: 고객이 먼저 카메라를 켜고, 엔지니어가 '연결 준비'를 누르면 초록색으로 바뀌는지 본다.
- **제약**: 잠깐 끊겨도 '보고 있어요'가 그대로 남는다. 기사님이 오래 안 와도 시간 제한이나 추가 안내가 없다. 음소거·볼륨 버튼이 없다.

### JOIN-07 · 카메라 전/후면 전환 ✅
- **동작**: 🔄를 누르면 통화를 끊지 않고 앞·뒤 카메라를 바꾼다. 엔지니어 화면도 같이 바뀐다. 기사님과 연결되기 전에 바꿔도, 연결되면 바꾼 카메라가 간다. 기사님이 원격으로 바꿀 수도 있다([CALL-10](#call-10--고객-카메라-원격-전환-)). 전환은 (1) 지금 카메라를 켠 채 새 카메라 열기 → (2) 안 되면 지금 카메라를 끄고 열기 → (3) 그래도 안 되면 원래 카메라로 되돌리기 순서로 시도한다. 실패하면 안내 없이 원래 카메라를 쓴다.
- **확인**: (1) 연결된 상태에서 🔄 → 엔지니어 화면이 끊김 없이 바뀐다. (2) '기사님을 기다리는 중…'일 때 🔄 → 엔지니어가 '연결 준비' → 엔지니어 화면에 바꾼 카메라 영상이 나온다.
- **제약**: 카메라 두 개를 동시에 못 여는 폰은 (2)로 넘어가면서 영상이 잠깐(1초 이내) 끊긴다. 바꾸면 손전등은 꺼진다.

### JOIN-08 · 고객이 종료 ✅
- **동작**: 빨간 '종료'를 누르면 확인 없이 바로 끝난다. 고객 화면은 '상담이 끝났습니다 / 이용해 주셔서 감사합니다.'로 바뀌고 카메라·마이크가 꺼진다. 엔지니어 화면에는 '고객님이 통화를 종료했어요'와 해결 여부 질문이 뜬다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).
- **제약**: 잘못 눌렀으면 문자 링크를 다시 열고 '카메라 켜기'를 누르면 이어진다(엔지니어가 아직 답하지 않았을 때만). 고객이 종료해도 세션은 엔지니어가 답해야 '종료'가 된다.

### JOIN-09 · 연결 실패 안내 ✅
- **동작**: 연결이 완전히 실패하면 '연결이 끊겼어요 / 아래 버튼을 눌러 다시 연결해 주세요.'와 큰 '다시 연결' 버튼이 나온다. 누르면 시작 화면으로 돌아가고, '카메라 켜기'를 다시 누르면 재연결된다.
- **제약**: 자동으로 다시 시도하지 않아 버튼을 두 번('다시 연결', '카메라 켜기') 눌러야 한다. 실패하면 고객 쪽은 통화 채널에서 나가므로, 엔지니어 화면은 '고객님 접속 대기 중…'으로 바뀐다.

### JOIN-10 · 카카오톡 앱 안 브라우저 안내 ✅
- **동작**: 링크를 메신저·SNS 앱 안 브라우저로 열면 '카메라 켜기' 대신 안내 화면이 먼저 나온다. 아이폰 카톡 안에서는 카메라가 켜지지 않고 안드로이드도 불안정하기 때문이다.
  - **카카오톡·라인**: 화면이 뜨자마자 **자동으로 폰의 기본 인터넷 앱(사파리·크롬·삼성 인터넷)으로 다시 연다**. 고객이 누를 것은 늘지 않는다. 자동으로 안 넘어가면 '인터넷 앱으로 열기' 버튼을 누른다.
  - **네이버·인스타그램·페이스북·밴드·다음 앱**: 자동으로 넘길 방법이 없어서 '⋯ 또는 공유 → 다른 브라우저로 열기' 안내와 '링크 복사' 버튼을 보여 준다.
  - 어느 경우든 아래에 작은 '이대로 계속하기'가 있어 그 자리에서 카메라를 켜 볼 수 있다.
- **확인**: 엔지니어가 '카톡 등으로 공유'로 링크를 카톡에 보낸다. 고객 폰 카톡에서 링크를 누르면 사파리(아이폰)나 기본 인터넷 앱(안드로이드)이 열리고 '카메라 켜기' 화면이 나오는지 본다.
- **제약**: 앱을 알아보는 방법은 브라우저가 알려 주는 기기 정보(User-Agent)라서, 앱이 표시를 바꾸면 못 알아볼 수 있다. 카카오톡의 외부 열기는 공식 문서에 없는 방식이라 카톡 업데이트로 막힐 수 있다(그때는 버튼·안내로 대신한다). 자동으로 넘어가면 앱 안과 인터넷 앱에서 `link_opened`가 두 번 기록된다.

## 4. 영상·음성 통화 (CALL)

### CALL-01 · 엔지니어 '연결 준비' ✅
- **동작**: 세션 화면 아래 '🎤 연결 준비'를 눌러야 통화 대기를 시작한다. 누르기 전에는 마이크 권한을 묻지 않는다. 처리 중에는 버튼이 '준비 중…'으로 바뀌고 잠긴다. 버튼 아래에 세션을 끝내는 작은 버튼('세션 닫기' 또는 '통화 종료', [ROOM-10](#room-10--종료와-출장-없이-해결-입력-))이 있다.
- **제약**: 세션 화면을 새로고침하면 다시 눌러야 한다. 같은 세션을 폰과 PC에서 둘 다 '연결 준비'하면 연결이 꼬인다 → [BUG-04](#bug-04--같은-역할이-두-기기에서-들어오면-연결이-꼬임-중간)

### CALL-02 · 마이크 없이 '보기만' ✅
- **동작**: 엔지니어가 마이크를 거부하거나 마이크가 없어도 영상은 보고, '마이크 꺼짐(보기만)'이 표시된다. 이때 고객은 기사님 목소리를 못 듣는다.
- **제약**: 통화 중에 마이크를 켜고 끌 버튼이 없다. 아이폰에서 마이크를 거부한 채 들어가면 브라우저 자동 재생 제한 때문에 고객 영상이 안 나올 수 있다(실기기 확인 필요). 아이폰 엔지니어는 마이크를 허용하고 쓴다.

### CALL-03 · 자동 연결 ✅
- **동작**: 엔지니어가 '연결 준비'를 누른 상태이고 고객이 카메라를 켰으면, 누가 먼저 들어왔든 추가 조작 없이 연결된다.
- **확인**: 들어오는 순서를 바꿔 두 번 해 본다. 두 번 다 엔지니어 화면에 고객 영상이 떠야 한다.
- **제약**: 시그널링(Supabase Realtime) 연결 자체가 실패하면 안내 없이 대기 문구만 계속 보인다. 권한 거부만은 따로 안내한다([CALL-12](#call-12--엔지니어-사칭-차단-)).

### CALL-04 · 엔지니어 통화 화면 ✅
- **동작**: 상태가 '고객님 접속 대기 중…' → '고객님 접속됨 — 연결 중…' → 검은 영역에 '연결 중…' → 고객 영상 순서로 바뀐다. 고객 영상은 잘리지 않게 전체가 보이고 고객 목소리가 들린다. 영상 아래 빨간 '종료' 버튼이 있고, 대기 화면에도 끝내는 버튼이 있다([ROOM-10](#room-10--종료와-출장-없이-해결-입력-)).

### CALL-05 · 나갔다 들어오면 재연결 🚧
- **동작**: 한쪽이 새로고침하거나 나가면 남은 쪽은 대기 상태로 돌아간다. 나간 쪽이 다시 들어와 버튼('카메라 켜기' 또는 '연결 준비')을 누르면 남은 쪽은 아무것도 안 해도 다시 연결된다.
- **확인**: 연결 중에 고객 폰을 새로고침하고 '카메라 켜기'를 다시 눌러 본다.
- **제약**: 알아차리는 데 몇 초 걸릴 수 있다. 엔지니어 쪽이 네트워크 끊김 등으로 갑자기 나갔다가 곧바로 다시 들어오면 자동으로 다시 연결되지 않을 수 있다. 이때 엔지니어 화면은 '고객님 접속됨 — 연결 중…'에 멈추고, 고객은 '연결이 끊겼어요'가 뜬 뒤 버튼을 다시 눌러야 한다. 종료한 쪽은 다시 연결되지 않는다(끝난 화면이 되살아나지 않음).

### CALL-06 · 엔지니어가 종료 ✅
- **동작**: 엔지니어가 '종료'를 누르면 고객 화면이 바로 '상담이 끝났습니다'로 바뀌고 고객 카메라가 꺼진다. 엔지니어 마이크도 꺼진다. 엔지니어 화면은 [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)의 질문으로 간다.

### CALL-07 · 연결 실패 표시 ✅
- **동작**: 연결이 완전히 실패하면 엔지니어 화면에 '연결에 실패했어요 / 고객님께 링크를 다시 열어달라고 말씀해 주세요.'와 끝내는 버튼('통화 종료' 또는 '세션 닫기', [ROOM-10](#room-10--종료와-출장-없이-해결-입력-))이 나온다. 고객 화면은 [JOIN-09](#join-09--연결-실패-안내-)와 같다. 고객이 나가면 엔지니어 화면은 '고객님 접속 대기 중…'으로 바뀌고, 고객이 다시 들어오면 자동으로 연결된다.
- **제약**: 브라우저가 "완전 실패"로 판정할 때만 뜬다(수십 초 걸릴 수 있음). 잠깐 끊긴 상태는 표시하지 않고, 자동 복구(ICE 재시작)도 없다.

### CALL-08 · 레이저 포인터 ✅
- **동작**: 연결된 뒤 엔지니어가 영상을 누르면 고객 화면의 같은 위치에 **빨간 동그라미**(가운데가 비어 버튼을 가리지 않음, 두근거리는 효과)가 나타나고 **3초 뒤 서서히 사라진다**. 새로 누르면 이전 것을 바로 대체한다. 엔지니어 화면에도 같은 동그라미가 떠서 고객에게 어디가 보이는지 알 수 있다. 영상 아래에 '영상을 누르면 고객님 화면에 빨간 동그라미가 표시돼요' 안내가 있다.
- **확인**: 연결 후 엔지니어가 영상의 네 모서리 근처와 가운데를 차례로 눌러 본다. 고객 화면에서 같은 곳에 동그라미가 뜨고 3초 뒤 사라지는지, 모서리를 눌러도 고객 화면에서 잘리지 않는지 본다.
- **제약**: 동그라미는 화면 위치에 붙어 있어서, 고객이 폰을 움직이면 가리킨 물체에서 벗어난다(그래서 3초만 보여 준다). 정확히 가리켜야 하면 폰을 잠시 고정해 달라고 말로 안내한다. 영상 밖 검은 여백을 누르면 무시한다. 고객은 가리킬 수 없다(보기만). 앞면 카메라로 바꿔도 좌우가 뒤집혀 보이지 않으므로 위치는 그대로 맞는다.

### CALL-09 · 프리즈 프레임 + 드로잉 ✅
- **동작**: 연결된 뒤 엔지니어가 '⏸ 멈추고 그리기'를 누르면 **엔지니어가 보던 장면이 사진으로 떠져** 두 화면에 똑같은 정지 화면이 뜬다. 엔지니어가 손가락으로 그리면 빨간 선(흰 테두리)이 실시간으로 고객 화면에도 그려진다. 버튼은 '▶ 다시 보기'(멈춤 해제, 선도 사라짐), '↶ 되돌리기'(마지막 선 지우기), '지우기'(선 전부 지우기). 고객 화면 위쪽 표시는 주황색 '기사님이 화면을 멈추고 설명 중이에요'로 바뀐다. 멈춘 동안 고객 카메라 영상은 뒤에서 계속 전송된다.
- **확인**: 연결 후 '⏸ 멈추고 그리기' → 고객 폰에도 같은 장면이 멈춰 보이는지, 그린 선이 같은 자리에 나타나는지, 되돌리기·지우기·다시 보기가 고객 화면에도 반영되는지 본다. 고객이 폰을 움직여도 멈춘 화면과 선은 그대로여야 한다.
- **제약**: 정지 화면은 연결(데이터 채널)로만 보낼 수 있어서, 연결이 불안정하면 '연결이 불안정해 화면을 멈추지 못했어요. 다시 눌러주세요.'가 나온다. 사진은 긴 변 1280px JPEG로 줄여 보낸다(보통 수십~수백 KB). 연결이 끊기면 양쪽 모두 멈춤이 풀린다. 멈춘 동안에는 레이저 포인터 대신 그리기만 된다. 고객은 그릴 수 없다. 색·굵기 선택, 도형·글자 도구는 없다.

### CALL-10 · 고객 카메라 원격 전환 ✅
- **동작**: 연결된 뒤 엔지니어가 '🔄 카메라'를 누르면 고객 폰의 앞·뒤 카메라가 바뀐다([JOIN-07](#join-07--카메라-전후면-전환-)과 같은 방식). 고객 화면에는 '기사님이 앞(뒤) 카메라로 바꿨어요'가 크게 2.5초 뜬다. 엔지니어 화면 아래에 '고객 카메라: 뒤 · 손전등 꺼짐'처럼 지금 상태가 표시된다. 결과가 올 때까지 버튼은 잠긴다(최대 6초).
- **확인**: 연결 후 엔지니어가 '🔄 카메라'를 누른다. 영상이 앞 카메라(고객 얼굴)로 바뀌고, 고객 폰에 안내 문구가 뜨고, 엔지니어 화면 상태 표시가 '앞'으로 바뀌는지 본다. 아이폰과 안드로이드 고객 모두 해 본다.
- **실기기 확인**: 2026-09-24 엔지니어 PC ↔ 고객 아이폰에서 원격 전환이 고객 탭 없이 바로 됨.
- **제약**: 폰이 고객의 탭 없이 카메라를 못 바꾸게 막으면(확인한 아이폰에서는 막히지 않았지만 기종·버전에 따라 생길 수 있음) 고객 화면에 '기사님이 카메라를 바꿔 달라고 하세요 / 🔄 바꾸기' 버튼이 뜨고, 엔지니어 화면에는 '고객님께 화면의 바꾸기를 눌러 달라고 말씀해 주세요'가 뜬다. 전환에 실패하면 '고객 폰에서 바꾸지 못했어요'가 뜬다. 멈춘 화면([CALL-09](#call-09--프리즈-프레임--드로잉-))에서는 버튼이 보이지 않는다.

### CALL-11 · 고객 손전등 원격 켜기 ✅
- **동작**: 고객 폰 카메라가 손전등을 지원하면 엔지니어 화면에 '🔦 손전등' 버튼이 나온다. 누를 때마다 고객 폰 손전등이 켜지고 꺼진다(켜져 있으면 버튼이 노란색). 고객 화면에는 '기사님이 손전등을 켰어요(껐어요)'가 뜬다. 통화가 끝나면 카메라와 함께 꺼진다.
- **확인**: 안드로이드 고객 폰(뒤 카메라)으로 연결한 뒤 엔지니어 화면에 '🔦 손전등'이 보이는지, 누르면 고객 폰 플래시가 켜지고 영상이 밝아지는지 본다. 아이폰 고객 폰에서도 버튼이 보이는지 확인한다.
- **실기기 확인**: 2026-09-24 엔지니어 PC ↔ 고객 아이폰에서 손전등 켜기·끄기가 됨.
- **제약**: 지원 여부는 고객 폰 브라우저가 알려 주는 대로 판단한다. 확인한 아이폰은 되지만 오래된 iOS에서는 안 될 수 있다(안 되면 버튼이 아예 안 보인다). 안드로이드 고객 폰은 아직 확인하지 않았다. 앞 카메라에는 손전등이 없어서, 카메라를 바꾸면 버튼이 사라지거나 꺼진다.

### CALL-12 · 엔지니어 사칭 차단 🚧
- **동작**: 통화 신호 채널을 방마다 일방통행 두 개로 나눈 **비공개 채널**로 쓴다.
  - **엔지니어 → 고객** 채널에 신호(응답·포인터·원격 카메라 명령·종료)를 보낼 수 있는 건 **로그인한 그 세션의 주인뿐**이다. Supabase 서버가 보낼 때마다 로그인 토큰(JWT)의 사용자와 세션 주인을 DB 규칙으로 대조한다. 고객 폰은 이 채널에서 온 신호만 믿는다. 그래서 링크를 가진 제3자나 다른 엔지니어 계정은 엔지니어 행세를 해 고객 카메라를 보거나 통화를 끊을 수 없다.
  - **고객 → 엔지니어** 채널은 링크를 연 사람 누구나 보낼 수 있다(고객은 로그인이 없으므로).
  - 두 채널 모두 종료·만료된 세션이면 새로 들어올 수 없다.
  - 채널이 거부하면 엔지니어 화면에 '통화 권한을 확인하지 못했어요 / 로그인이 풀렸을 수 있어요'와 '다시 로그인' 버튼이, 고객 화면에 '종료된 연결이에요'가 나온다.
- **확인**: [OPS-04](#ops-04--db-준비-)와 [OPS-05](#ops-05--realtime-공개-채널-끄기-)를 적용한 뒤 평소처럼 통화가 되는지 본다.
- **제약**:
  - 운영 Supabase에서 아직 확인하지 않았다(규칙은 로컬 Postgres, 채널 동작은 모의 테스트로만 확인). 특히 로그인 없는 고객(publishable 키)이 비공개 채널에 들어갈 수 있는지가 확인 전이다.
  - 링크를 가진 사람은 여전히 **고객으로** 들어올 수 있다. 이때 보이는 건 그 사람 자신의 카메라뿐이지만 진짜 고객 연결을 끊을 수는 있다 → [BUG-04](#bug-04--같은-역할이-두-기기에서-들어오면-연결이-꼬임-중간)
  - 링크를 가진 사람은 엔지니어 쪽 신호를 엿들을 수 있다(엔지니어 폰의 네트워크 주소가 보임, 영상·음성은 안 보임).
  - 이미 들어와 있던 연결이 세션 종료 순간 서버에서 끊기는지는 확인하지 않았다(종료 시 양쪽 화면은 스스로 채널을 나간다).
- **관련 코드**: `src/lib/webrtc/call.ts`, `supabase/schema.sql`(맨 아래 채널 규칙)

## 5. 연결 품질·TURN (NET)

### NET-01 · TURN 포함 연결 서버 ✅
- **동작**: 통화를 시작할 때마다(엔지니어 '연결 준비', 고객 '카메라 켜기') 서버에서 연결 서버 목록을 받는다. Google STUN과 Cloudflare TURN이 들어 있다. Cloudflare 키는 서버에만 있고, 폰에는 2시간짜리 임시 자격증명만 내려간다. 브라우저가 막는 53번 포트 주소는 뺀다.
- **확인**: 엔지니어 화면에 노란 TURN 경고가 없으면 정상이다.
- **제약**: 자격증명은 버튼을 누를 때 한 번만 받는다. 2시간 넘게 대기하거나 통화하면 TURN이 안 될 수 있다.

### NET-02 · 유효한 코드에만 발급 ✅
- **동작**: 없는 코드, 종료·만료된 세션에는 TURN 자격증명을 주지 않는다.
- **제약**: 호출 횟수 제한이 없다 → [BUG-15](#bug-15--고객용-서버-기능에-횟수-제한검사-없음-낮음보안)

### NET-03 · TURN 실패해도 통화는 계속 + 경고 ✅
- **동작**: TURN을 못 받으면(키 미설정, Cloudflare 오류 등) STUN만으로 연결을 시도한다. 엔지니어 화면에 노란 경고 '⚠ TURN 서버 없이 연결 중 — 모바일망끼리는 실패할 수 있어요 (원인)'이 뜬다.
- **확인**: 경고의 괄호 안이 원인이다. `미설정`은 Vercel 환경 변수 누락, `cloudflare 401/403`은 토큰 오류, `cloudflare 404`는 Key ID 오류.
- **제약**: 고객 화면에는 경고가 없다. 세션 화면을 열어 둔 채 24시간이 지나면 '연결 준비' 때 '세션이 종료됐거나 만료됐어요' 경고가 뜬다(새로 열면 만료 안내 화면이 나온다).

### NET-04 · 서울 리전 ✅
- **동작**: 서버 기능은 Vercel 서울(icn1)에서 실행된다. Supabase도 서울 리전으로 만들었다.

## 6. 지표·데이터 (DATA)

### DATA-01 · 지표 이벤트 목록 🚧
- **동작**: 아래 이벤트를 Supabase `events` 표에 남긴다. 각 줄에는 세션, 누가(`engineer`/`customer`), 이름, 부가정보(`props`), 시각이 들어간다.

  | 이벤트 | 언제 | 누가 | 부가정보 |
  |---|---|---|---|
  | `room_created` | 세션을 만들 때 | 엔지니어 | |
  | `link_opened` | 고객이 유효한 링크를 열 때 | 고객 | `ua` (브라우저 정보), `inapp` (카카오톡 등 앱 안 브라우저면 앱 이름, 아니면 null) |
  | `camera_granted` | 고객이 카메라·마이크를 허용할 때 | 고객 | |
  | `camera_denied` | 고객이 카메라나 마이크 중 하나라도 거부했거나, 카메라·마이크를 못 쓸 때 (마이크만 거부해도 기록됨) | 고객 | |
  | `connected` | 연결되고 1초 뒤 | 고객 | `relay`(TURN 경유 여부), `turn`(TURN 자격증명 받았는지) |
  | `relay_used` | `connected`에서 TURN을 거쳤을 때 | 고객 | |
  | `ended` | 엔지니어가 세션을 종료할 때(해결 여부 답 또는 '세션 닫기'). 세션당 한 번 | 엔지니어 | `duration_sec`, `resolved_remotely`(true/false, 연결된 적 없이 닫으면 null) |
  | `resolved_remotely` | 종료 질문에 '네'를 골랐을 때 | 엔지니어 | |
  | `pointer_used` | 엔지니어가 레이저 포인터를 처음 쓸 때 ([CALL-08](#call-08--레이저-포인터-)). 세션 화면을 열 때마다 1번 | 엔지니어 | |
  | `freeze_used` | 엔지니어가 화면 멈춤을 처음 쓸 때 ([CALL-09](#call-09--프리즈-프레임--드로잉-)). 세션 화면을 열 때마다 1번 | 엔지니어 | |

- **확인**: Supabase → Table Editor → `events`에서 세션(`room_id`)으로 걸러 본다.
- **제약**: 기록에 실패해도 기능은 멈추지 않고, 실패한 기록은 사라진다. 연결 실패는 이벤트가 없다. 정확도 문제는 [DATA-02](#data-02--핵심-지표-계산법-) 참고.

### DATA-02 · 핵심 지표 계산법 🚧
- **동작**: README의 지표 네 가지는 지금 데이터로 이렇게 뽑는다. 계산해서 보여 주는 화면은 없어서 Supabase에서 직접 조회해야 한다.

  | 지표 | 계산 | 주의 |
  |---|---|---|
  | 원격 해결률 | `resolved_remotely`가 true 또는 false인 세션 중 true 비율 (`rooms` 표) | 값이 비어 있는(null) 세션은 빼고 센다. 고객과 연결되지 않은 채 닫은 세션과, 엔지니어가 답하지 않은 세션이 null이다 |
  | 링크 → 카메라 허용 도달률 | `camera_granted`가 있는 세션 ÷ `link_opened`가 있는 세션 | 이벤트 개수가 아니라 **세션 단위**로 센다. `link_opened`에는 새로고침과 문자·카톡 미리보기 방문, 카톡에서 인터넷 앱으로 자동 전환한 두 번째 열기가 섞인다 |
  | 연결 실패율 / TURN 사용 비율 | 실패율 ≈ `camera_granted`는 있는데 `connected`가 없는 세션 비율. TURN 비율 = `connected`가 있는 세션 중 `relay_used`도 있는 세션 비율 | 실패 이벤트가 없어 실패율은 추정치다. 엔지니어가 '연결 준비'를 안 눌렀거나 고객이 기다리다 나간 세션도 실패로 잡혀 **실제보다 높게** 나온다. [NFR-05](#nfr-05--영상-연결은-브라우저-기본-기능으로-)의 5% 기준과 비교할 때는 이런 세션을 빼고 본다. TURN 경유는 고객 쪽 경로만 보고 판단한다. `connected`는 재연결마다 다시 쌓인다 |
  | 세션당 평균 시간 | `ended` 중 `resolved_remotely`가 null이 아닌 것의 `duration_sec` 평균 | **통화 시간이 아니라 세션을 만든 때부터** 잰다. 링크 보내고 기다린 시간이 들어간다. 고객과 연결되지 않은 채 닫은 세션(null)은 빼야 평균이 부풀지 않는다 |

### DATA-03 · 세션 데이터 ✅
- **동작**: 세션마다 담당 엔지니어, 접속 코드, 상태, 원격 해결 여부, 만든 시각, 만료 시각(+24시간), 종료 시각을 저장한다.
- **제약**: 고객 이름·전화번호 칸이 DB에 있지만 입력하는 화면이 없어 항상 비어 있다. 엔지니어 계정을 지우면 그 사람의 세션과 지표도 함께 지워진다.

### DATA-04 · 고객 쪽 기록 제한 ✅
- **동작**: 고객 폰이 보낼 수 있는 기록은 `camera_granted`, `camera_denied`, `connected`, `relay_used` 네 가지뿐이다. 유효한(종료·만료되지 않은) 세션 코드가 있을 때만 저장된다. `link_opened`는 서버가 직접 남긴다.
- **제약**: 부가정보 내용·크기를 검사하지 않고 횟수 제한도 없다 → [BUG-15](#bug-15--고객용-서버-기능에-횟수-제한검사-없음-낮음보안)

### DATA-05 · 데이터 접근 권한 ✅
- **동작**: 고객은 DB에 직접 접근하지 못하고 모든 조회·기록이 서버를 거친다. DB 전체 권한 키는 서버에만 있다. 엔지니어는 자기 세션과 그 기록만 볼 수 있고, 기록은 읽기만 된다.
- **제약**: 엔지니어가 앱을 거치지 않고 Supabase에 직접 요청하면 자기 세션을 새로 만들거나(원격 해결 '네'로 채운 가짜 세션 포함), 값을 바꾸거나, 지울 수 있다. 세션을 지우면 그 세션의 기록(events)도 함께 지워진다. 즉 원격 해결률은 엔지니어가 조작할 수 있는 숫자다. 통화 신호 채널 권한은 [CALL-12](#call-12--엔지니어-사칭-차단-)를 따른다.

## 7. 공통 원칙 (NFR)

### NFR-01 · 고객은 탭 두 번 ✅
링크 → '카메라 켜기' → '허용'. 로그인·설치·앱 없음.
- **제약**: 정상 흐름 기준이다. 카카오톡·라인 안에서 열면 인터넷 앱으로 자동 전환되고, 그 밖의 앱에서 열면 고객이 직접 인터넷 앱으로 열어야 한다 → [JOIN-10](#join-10--카카오톡-앱-안-브라우저-안내-). 연결이 실패하면 '다시 연결'과 '카메라 켜기'를 또 눌러야 한다 → [JOIN-09](#join-09--연결-실패-안내-)

### NFR-02 · 어르신 기준 화면 🚧
한국어, 큰 버튼, 한 화면에 한 가지 행동. 실수로 화면이 확대되지 않게 모든 화면(엔지니어 화면 포함)의 배율을 고정했다.
- **제약**: 안드로이드에서는 작은 글씨를 손가락으로 확대할 수도 없다(아이폰은 확대됨). 필요하면 고정을 풀지 결정해야 한다. 폰이 다크 모드면 글씨와 버튼이 잘 안 보인다 → [BUG-10](#bug-10--다크-모드에서-글씨버튼-대비가-낮음-낮음)

### NFR-03 · 카메라·마이크는 버튼을 누른 뒤에만 ✅
iOS 정책 때문에, 고객 '카메라 켜기'와 엔지니어 '연결 준비'를 누른 뒤에만 권한을 묻는다.

### NFR-04 · 폰에 세션 정보 저장 안 함 ✅
고객 폰은 공용일 수 있으므로 브라우저 저장소(localStorage)를 쓰지 않는다. 엔지니어 로그인은 쿠키만 쓴다.

### NFR-05 · 영상 연결은 브라우저 기본 기능으로 ✅
관리형 서비스(LiveKit 등) 없이 브라우저 내장 WebRTC로 폰끼리 직접 연결한다. 직접 연결이 안 될 때만 Cloudflare TURN이 중계한다. 연결 실패율이 5%를 넘는 상태가 이어지거나 재연결 안정화에 2주 이상 걸리면 LiveKit 전환을 다시 검토한다 (README 결정).

---

### NFR-06 · 통화 중 화면 꺼짐 방지 ✅
고객이 '카메라 켜기', 엔지니어가 '연결 준비'를 누르면 통화가 끝날 때까지 폰 화면이 자동으로 꺼지지 않게 한다. 고객은 폰을 비추기만 하고 화면을 건드리지 않아 자동 잠금으로 끊기기 쉽기 때문이다. 앱이나 다른 탭에 갔다 돌아오면 다시 건다.
- **확인**: 폰의 자동 잠금을 30초로 해 두고 통화한다. 30초가 지나도 화면이 꺼지지 않는지 본다.
- **제약**: 브라우저가 지원하지 않거나 저전력 모드이면 안내 없이 적용되지 않는다(아이폰은 iOS 16.4 이상).

## 8. 운영 설정 (OPS)

### OPS-01 · 환경 변수 ✅
Vercel → Settings → Environment Variables에 5개를 넣고 **Redeploy**한다. 값을 바꿔도 다시 배포해야 반영된다.

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase publishable 키 (`sb_publishable_…`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase secret 키 (`sb_secret_…`). 서버 전용 |
| `CLOUDFLARE_TURN_KEY_ID` | Cloudflare → Realtime → TURN의 Key ID |
| `CLOUDFLARE_TURN_API_TOKEN` | 같은 곳의 API Token |

### OPS-02 · Vercel 배포 보호 끄기 ✅
Vercel → Settings → Deployment Protection → **Vercel Authentication 끄기**. 켜져 있으면 고객 폰에 Vercel 로그인 화면이 뜬다.

### OPS-03 · 엔지니어 계정 만들기 ✅
Supabase → Authentication → Users → Add user → Create new user. **Auto Confirm User를 체크**해야 바로 로그인된다.

### OPS-04 · DB 준비 ✅
Supabase → SQL Editor에서 `supabase/schema.sql` 전체를 실행한다. 여러 번 실행해도 된다.
- **제약**: 이미 있는 표는 건너뛰므로, 나중에 칸을 바꾸면 이 파일을 다시 실행하는 것만으로는 기존 DB에 반영되지 않는다. 규칙(정책)·함수는 다시 실행하면 새로 반영된다.

### OPS-05 · Realtime 공개 채널 끄기 🚧
Supabase → Realtime → Settings → **Allow public access(공개 채널 허용) 끄기**. 켜 두면 비공개 설정을 뺀 채널이 [CALL-12](#call-12--엔지니어-사칭-차단-)의 규칙을 거치지 않을 수 있다.
- **순서**: ① [OPS-04](#ops-04--db-준비-)로 규칙을 넣고 ② 새 코드를 배포하고 ③ 통화가 되는지 확인한 **뒤에** 끈다.
- **제약**: 아직 운영 프로젝트에 적용하지 않았다.

## 알려진 문제

코드로 확인된 버그와 빈틈이다. 우선순위는 **높음**(핵심 흐름이나 핵심 지표가 깨짐) · **중간** · **낮음**. 해결된 항목도 번호를 남겨 두고 **상태** 줄에 해결 날짜를 적는다.

### BUG-01 · 고객이 먼저 종료하면 엔지니어 화면이 멈춤 (높음)
**상태**: ✅ 해결 (2026-09-24). 고객이 종료하면 엔지니어 화면에 '고객님이 통화를 종료했어요'와 해결 여부 질문이 뜬다.

고객이 '종료'를 누르면 엔지니어 화면이 종료 버튼 없는 '고객님 접속됨 — 연결 중…'에 멈춘다. 그래서 '출장 없이 해결됐나요?'를 입력할 수 없고, 세션은 '연결됨'으로 남으며, 핵심 지표(원격 해결률)가 빠진다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-), [JOIN-08](#join-08--고객이-종료-)

### BUG-02 · 고객이 안 들어온 세션을 끝낼 수 없음 (높음)
**상태**: ✅ 해결 (2026-09-24). 모든 단계에 끝내는 버튼을 두고, 연결된 적 없는 세션은 '세션 닫기'로 해결 여부 없이 닫는다.

'연결 준비' 전 화면과 대기 화면에 종료 버튼이 없다. 고객이 끝내 안 들어온 세션은 대시보드에 '대기 중'으로 계속 쌓인다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-), [CALL-04](#call-04--엔지니어-통화-화면-)

### BUG-03 · 연결 전에 카메라를 바꾸면 엔지니어에게 검은 화면 (높음)
**상태**: ✅ 해결 (2026-09-24). 카메라를 바꾸면 이후에 맺는 연결에도 바꾼 카메라가 간다.

고객이 '기사님을 기다리는 중…'일 때 🔄를 누르면, 연결됐을 때 엔지니어 화면에 영상이 안 나온다. 통화 중에 바꾼 뒤 재연결될 때도 같다. 관련: [JOIN-07](#join-07--카메라-전후면-전환-), [CALL-05](#call-05--나갔다-들어오면-재연결-)

### BUG-04 · 같은 역할이 두 기기에서 들어오면 연결이 꼬임 (중간)
**상태**: 🚧 일부 해결 (2026-09-24). '연결 준비' 두 번 누르기는 막았다. 두 기기에서 들어오는 경우는 남아 있다.

엔지니어가 같은 세션을 폰과 PC에서 둘 다 '연결 준비'하거나 버튼을 두 번 누르면, 또는 고객 링크를 두 기기에서 열면 서로의 연결을 끊는다. 링크가 새면 진행 중인 상담에 다른 사람이 끼어들 수 있다. 관련: [ROOM-03](#room-03--초대-링크-유효기간-), [CALL-01](#call-01--엔지니어-연결-준비-)

### BUG-05 · 종료·실패 뒤에 화면이 되살아남 (중간)
**상태**: ✅ 해결 (2026-09-24). 고객은 종료·실패하면 채널에서 나가고, 엔지니어는 직접 종료하면 채널에서 나간다. 고객이 먼저 종료한 경우에만 엔지니어가 남아 있다가, 고객이 링크를 다시 열면 이어받는다(의도한 동작).

종료하거나 실패한 뒤에도 신호 채널이 연결된 채로 남는다. 그래서 상대가 다시 들어오면 '상담이 끝났습니다'나 '출장 없이 해결됐나요?' 화면이 통화 화면으로 돌아간다. 고객 쪽이 되살아나면 이미 꺼진 카메라로 연결돼 엔지니어에게 검은 화면이 간다. 엔지니어 쪽이 되살아나면(고객이 링크를 다시 연 경우) 영상은 정상이지만 '출장 없이 해결됐나요?' 질문이 사라져 '종료'를 다시 눌러야 한다. 관련: [CALL-05](#call-05--나갔다-들어오면-재연결-)

### BUG-06 · 대시보드 시각이 한국 시간이 아닐 수 있음 (중간)
**상태**: ✅ 해결 (2026-09-24). 시각을 한국 시간(Asia/Seoul)으로 고정했다.

세션 시각을 서버에서 시간대 지정 없이 만든다. Vercel 서버는 UTC라서 9시간 이르게 보일 가능성이 높다. 관련: [ROOM-04](#room-04--최근-세션-목록-)

### BUG-07 · 만료된 세션이 엔지니어 화면에서 살아 있는 것처럼 보임 (중간)
**상태**: ✅ 해결 (2026-09-24). 대시보드는 '만료'로, 세션 화면은 만료 안내로 보여 주고 공유 버튼·통화를 숨긴다. DB 상태는 바꾸지 않는다.

24시간이 지난 세션도 대시보드에 '대기 중'으로, 세션 화면에 공유 버튼과 함께 보인다. 쓸 수 없는 링크를 보내게 된다. '연결 준비'를 누르면 그제야 '세션이 종료됐거나 만료됐어요' 경고가 뜬다. 관련: [ROOM-03](#room-03--초대-링크-유효기간-), [NET-03](#net-03--turn-실패해도-통화는-계속--경고-)

### BUG-08 · 로그인 후 이동 주소 검사에 빈틈 (중간·보안)
`/login?next=/\다른사이트` 같은 링크로 로그인하면 로그인 직후 외부 사이트로 넘어갈 수 있다. 가짜 로그인 링크로 엔지니어를 속이는 데 쓰일 수 있다. 관련: [AUTH-04](#auth-04--엔지니어-화면-보호-)

### BUG-09 · 통화 신호 채널에 접근 제한이 없음 (중간·보안)
**상태**: 🚧 일부 해결 (2026-09-24). 엔지니어 사칭과 종료·만료된 세션 입장은 막았다([CALL-12](#call-12--엔지니어-사칭-차단-), 운영 적용·확인 전). 링크를 가진 사람이 고객으로 끼어드는 문제는 [BUG-04](#bug-04--같은-역할이-두-기기에서-들어오면-연결이-꼬임-중간)와 함께 남아 있다.

(해결 전 내용) 신호 채널(`room:{세션 ID}`)이 공개 채널이다. 세션 ID는 고객 페이지에 담겨 내려가므로, 링크를 연 적 있는 사람은 진행 중인 통화에 끼어들거나 끊는 신호를 보낼 수 있다. 링크가 만료돼 고객 페이지가 더 이상 안 열려도 마찬가지다. 종료 처리된 세션은 통화 자체가 열리지 않으므로 해당 없다. 관련: [DATA-05](#data-05--데이터-접근-권한-)

### BUG-10 · 다크 모드에서 글씨·버튼 대비가 낮음 (낮음)
폰이 다크 모드면 배경이 거의 검게 바뀌는데, 검은 버튼과 회색 글씨는 그대로라 잘 안 보인다. 관련: [JOIN-02](#join-02--시작-화면-)

### BUG-11 · 새 세션 버튼 중복 클릭 (낮음)
'+ 새 원격 A/S 시작'이 처리 중에 잠기지 않아 여러 번 누르면 세션이 여러 개 생긴다. 관련: [ROOM-01](#room-01--새-세션-만들기-)

### BUG-12 · 종료 저장 실패 안내 없음 (낮음)
**상태**: ✅ 해결 (2026-09-24). 실패하면 '저장에 실패했어요. 다시 눌러주세요.'가 나온다.

'출장 없이 해결됐나요?' 저장이 실패해도 안내 없이 버튼만 다시 눌린다. 관련: [ROOM-10](#room-10--종료와-출장-없이-해결-입력-)

### BUG-13 · 404·오류 화면이 영어 기본 화면 (낮음)
없는 세션 주소나 세션 만들기 실패 때 Next.js 기본 영어 화면이 나온다. 관련: [AUTH-08](#auth-08--자기-세션만-보기-), [ROOM-01](#room-01--새-세션-만들기-)

### BUG-14 · 지표 정확도 (낮음)
`link_opened`에 새로고침·미리보기 방문이 섞이고, `connected`·`relay_used`가 재연결마다 쌓이고, TURN 경유를 고객 쪽만 보고 판단하고, `ended` 시간은 세션 생성부터 잰다. 연결 실패 이벤트는 없다. 당장은 [DATA-02](#data-02--핵심-지표-계산법-)의 주의사항대로 세션 단위로 세면 된다.

### BUG-15 · 고객용 서버 기능에 횟수 제한·검사 없음 (낮음·보안)
TURN 발급과 고객 지표 기록은 유효한 코드만 있으면 몇 번이든 부를 수 있고, 기록의 부가정보도 검사하지 않는다. 가짜 지표가 쌓이거나 TURN 사용량이 늘 수 있다. 관련: [NET-02](#net-02--유효한-코드에만-발급-), [DATA-04](#data-04--고객-쪽-기록-제한-)
