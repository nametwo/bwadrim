# 평면 앵커 추적 (src/lib/tracking)

엔지니어가 영상 위에 찍은 핀·선이 **고객이 폰을 움직여도 실제 사물(평면) 위에 붙어 있게** 하는 모듈.
앱·설치·추가 권한 없이 브라우저에서만 동작한다. SLAM이 아니라 "즉석 평면 타깃" 추적이다 —
A/S 대상(보일러 컨트롤러, 공유기 뒷면, 단말기, 두꺼비집, 명판)은 대부분 평면이기 때문.

## 원리

1. 엔지니어가 탭하면 그 순간 프레임(작업 해상도 그레이)이 **기준(ref)**, 탭 주변이 **ROI**가 된다.
2. 양쪽(엔지니어·고객)이 **각자 자기 영상에서** 같은 기준을 추적한다 → 네트워크 지연·시간 동기화 문제가 없다.
   - 엔지니어: 기준 = 자기가 보던 프레임 → `initialH = I`로 즉시 tracking.
   - 고객: 기준 이미지를 DataChannel로 받아 ORB 매칭으로 현재 프레임에서 찾고(searching) 이후 추적.
3. 결과는 호모그래피 `H: ref 픽셀 → frame 픽셀`. 주석(핀·선)은 ref 기준 0~1 좌표로 저장, 렌더링 때 H로 변환 → 원근까지 맞게 붙어 보인다.
4. 확신이 없으면 **숨긴다.** 틀린 곳을 가리키는 것이 안 보이는 것보다 훨씬 나쁘다 (옆 LAN 포트, 옆 차단기).
5. 고객 쪽에서 놓친 상태가 이어지면 기준 이미지+주석을 **카드**로 띄워 "이 부분을 비춰주세요"로 폴백.

## 파이프라인 (tracker.ts, cv/)

- 기준 설정: 피라미드 → ROI 안 FAST 코너(+Harris 점수, 격자 분산) → ORB(방향 + rBRIEF 256bit) 디스크립터
- 탐색/재검출(searching·lost): 현재 프레임 ORB → 해밍 매칭(비율 테스트·상호 확인) → RANSAC 호모그래피 → 검증(형상 타당성 + 기준 패치와의 NCC) → 통과해야만 tracking
- 추적(tracking): 피라미드 LK(순방향-역방향 검사) → RANSAC(ref 좌표 ↔ 현재 좌표, 체인 누적 없음) → 정제
  - 드리프트 억제: 주기적으로 기준과 직접 정렬(ORB 재매칭 또는 템플릿 정렬)
  - 점 보충: 워프된 ROI 안에서 새 코너 검출 → H⁻¹로 ref 좌표 부여
  - 모션 예측: 등속 가정으로 LK 초기값
- 상태: `searching → tracking ⇄ weak → lost → (재검출) → tracking`

모든 cv 코드는 **순수 TS, DOM·Worker 무관, 결정적(시드 고정)** — Node 벤치마크와 Worker에서 같은 코드가 돈다.
외부 CV 라이브러리 없음 (라이선스·번들 크기). 알고리즘은 공개 문헌 기반 자체 구현.

## 런타임 (브라우저)

```
<video> ─rVFC→ frame-source(작업 해상도 그레이, 1장만 in-flight) ─transfer→ tracker.worker ─→ TrackUpdate
                                                                                      │
             overlay(캔버스, object-fit 매핑 + H로 주석 렌더) ←──────────────────────┘
```

- 작업 해상도: 긴 변 320px. 앵커가 없으면 루프 정지(유휴 비용 0).
- 프레임레이트 상한: 고객 20fps, 엔지니어 30fps. 처리 시간이 길면 자동으로 낮춘다.
- `src/lib/webrtc/data-link.ts`가 RTCDataChannel을 감싼다. 추적 프로토콜은 그 인터페이스만 안다 (미디어 계층 격리 원칙).

## DataChannel 프로토콜 (`draw` 채널, 순서 보장·신뢰)

JSON 텍스트 메시지 + 기준 이미지용 바이너리 조각.

| 방향 | 메시지 |
|---|---|
| 엔지니어→고객 | `{"t":"anchor","anchor":AnchorDescriptor,"img":{"bytes":N,"mime":"image/jpeg","width":W,"height":H}}` 직후 바이너리 조각 ⌈N/16000⌉개 |
| 엔지니어→고객 | `{"t":"ann","anchorId":id,"ann":Annotation}` — 기존 앵커에 주석 추가 |
| 엔지니어→고객 | `{"t":"clear"}` |
| 고객→엔지니어 | `{"t":"status","anchorId":id,"state":TrackState}` — 상태가 바뀔 때만 |

- 기준 이미지는 컬러 JPEG(긴 변 640, 품질 0.8). 고객은 이를 (a) 추적 기준(작업 해상도 그레이로 변환) (b) 폴백 카드 이미지로 함께 쓴다.
- 수신측은 모든 메시지를 엄격히 검증하고 한도를 넘으면 버린다 (이미지 ≤ 512KB, 주석 ≤ 50개, 선 점 ≤ 500개, 좌표는 유한수·[-0.5, 1.5] 범위).
- 어떤 데이터도 저장하지 않는다 (localStorage 금지, 메모리에서만).

## UX

- 엔지니어: 탭 = 핀, 드래그 = 선. 활성 앵커의 ROI 안이면 같은 앵커에 추가, 밖이면 새 앵커(이전 것 대체). "지우기" 버튼 1개. 상태칩: "고객 화면에 표시 중 / 찾는 중 / 놓침".
- 고객: 아무 조작 없음. tracking이면 주석을 영상 위에, weak면 흐리게, 놓친 상태가 0.8초 이상이면 상단 카드("기사님이 표시한 곳을 비춰주세요").
- 핀: 흰 테두리 빨간 링(#FF3B30) + 중심점 + 맥동. 원근에 맞게 타원으로 그려지고 화면 크기는 14~80px로 제한.

## 품질 목표 (scripts/tracking-bench)

"틀린 표시" = 상태가 tracking/weak인데 핀 정답 위치와 오차 > 8px(작업 해상도) 이거나 핀이 화면 밖.

| 시나리오 | 추적률(보이는 프레임 중) | 오차 중앙값 | 틀린 표시 |
|---|---|---|---|
| 손떨림 | ≥ 95% | ≤ 2px | ≤ 0.5% |
| 이동·확대·기울임 | ≥ 85% | ≤ 3px | ≤ 1% |
| 반복 패턴(포트·차단기) | — | — | ≤ 1% |
| 무늬 없음 | trackable=false 또는 lost 허용 | — | ≤ 1% |
| 화면 밖 → 복귀 | 복귀 10프레임 내 재검출 ≥ 80% | — | ≤ 1% |
| 고객 최초 탐색(압축된 엔지니어 프레임이 기준) | 5프레임 내 ≥ 90% | — | ≤ 1% |

성능(데스크톱 Node, 320×240): tracking 프레임 중앙값 ≤ 5ms, 재검출 프레임 ≤ 15ms. 저가 안드로이드는 3~4배 느리다고 본다.
